# How to read a review package — notation key

Review packages (`review/<theme>/README.md`) use campaign shorthand that the
`/start` top page does not expand. This key defines each item in plain words.
It is a reading aid only: it changes no verdict, no stamp and no candidate.

**KB pattern ids (KB-01 … KB-81).** An entry in the pattern knowledge base
under [`patterns/`](../patterns/INDEX.md), generated by `patterns/build_index.py`.
Each KB entry names one review pattern that the campaign confirmed: the
mechanism, a static detection recipe, and its adjudication history. Examples:
KB-09 is a bare Rate module left beside the rate-bearing preview credit;
KB-16 is a JP font named in a stack but never loaded; KB-40 is the site-theme
`sigma.min.css` hotlink chain. A KB id is a pattern name, not a line number or
a severity. `patterns/NEGATIVE-LEDGER.md` records shapes that look like a hit
but are settled non-findings.

**P-numbers (P1–P11).** The numbered localize patterns a candidate is scored
against on the translation side (the campaign's localize checklist). The
number is a checklist item. Common ones: P1 foreign include kept instead of
repointed (KB-15); P3 credit fields and attribution (KB-10, KB-11); P4 a
cross-theme or original-delivery code import (KB-14); P5 asset/font host
violations (KB-17); P6 a missing or malformed interwiki-style frame (KB-07);
P7 a JP font load gap (KB-16); P9 header/title language (ruling 2, KB-57);
P10 untranslated visible text (KB-18); P11 prose links. When a package says
an item is "P7 FIXED", it means that checklist item was closed by an edit.

**Class (i) / (ii) / (iii).** The three dispositions of a T1 source-check
error:

- **(i)** breaks display at migration — fix the candidate (canonical first).
- **(ii)** a posting-procedure matter — rewritten or re-hosted to SCP-JP at
  posting; fix lanes leave the candidate byte-unchanged (for example a
  draft-host reference becoming `scp-jp.wdfiles.com`).
- **(iii)** a draft-form matter — the candidate's own `local--code` on the
  sanctioned draft host, valid at the draft stage.

**DISPOSITIONED.** Closed by a recorded decision with grounds, not necessarily
by an edit to the candidate; the package states which. It is distinct from
FIXED, which means an edit was actually applied — a DISPOSITIONED item may
leave the candidate byte-unchanged.

**Standing (standing classes, standing disposition).** Settled and in force —
the state recorded as the final one — not "outstanding" or still open.

**T1 … T5.** The campaign's five review tests behind the verdict:

- **T1** source check (the staff checker over the candidate source);
- **T2** render check (both engines, all viewports, on both sample pages);
- **T3** visual checklist walk (T2 screenshots plus the live pages);
- **T4** localize patterns and their follow-up diff (translated themes);
- **T5** translation text (visible text only).

"PASS / FINDINGS" in a package is the outcome of these tests; a finding can be
fixed or dispositioned with grounds. **Check 5** is not one of them — it was a
retired per-sample interaction measurement.

**T6 and above (T7, T8, T9, …).** Change-class labels from the port
classification, not review tests. They are a second series that reuses the
letter "T": in package prose T6 marks header/title-language handling (the P9
family), T7 marks credit-module CSS work, T8 marks a component swap, and T9
marks code delivery (own-code or base re-hosting). The five review tests are
T1–T5 only, so a T7 or T9 label means no test is missing or unrun.

**FINDINGS.** A stamp word meaning the test recorded findings and classified
them, not that the theme is blocked. The package's Status table carries the
operative verdict: a package whose Status says PASS is posted like any PASS
row even when a T line above it reads FINDINGS.

**Wave names (FIX-CREDIT-D, FIX3-S2EN, FIX4-IWA, FIX5, REFRESH3-F,
SWEEP-USAGE, …).** The campaign's recorded repair waves — named batches of
candidate edits. A wave lands as a canonical Git commit; that commit hash is
the "landing" a package cites for a repair. A package built before a landing
documents the as-built bytes; a "Post-package repairs" section records the
landing that postdates the build.

**Verdict stamp.** The generated `## Verdict stamp` block between the
`BEGIN/END GENERATED VERDICT STAMP` markers, produced by
`review/build_review.py`. It is the audit instrument's factual language:
`STALE` means the candidate file changed after the verdict head, so the
stamp's verdicts describe the pre-change file. Per the ruling on `/start`,
the record verdict stands and a STALE row is posted like a PASS row; this key
never edits a stamp region.

**Landing / package build.** "Landing" is the canonical commit that applied a
repair; "package build" is the earlier commit against which the package was
written. A flag whose cited bytes no longer match the landing is closed by
citing that landing — never by inventing a fix.
