**How verdict cells were filled.** Every one of the seven reports emits a single *combined* T2/T3 verdict per theme (A: `判定:` with T2/T3 sub-lines; B/C/D/D2/S2-A/S2-B: one `Verdict:` line). Per BRIEF §16, that one verdict is used for **both** the T2 and T3 cells, and each findings cell is marked `[combined T2/T3]` to say so. The source reports judge in their own vocabulary (`FINDINGS`, or `NO candidate-specific defect established / … blocking defect / … beyond cross-cutting`), not in the brief's four cell values, so the mapping applied is:
- report `FINDINGS` (≥1 render_check error or T3 display finding) → **FAIL**;
- report `NO candidate-specific defect established / NO candidate-specific blocking defect / NO candidate-specific defect beyond cross-cutting` (no theme-specific defect; only shared preview/draft-form/by-design items) → **PASS-WITH-NOTES**.

No report issues a bare `PASS` (its own PASS rule = both pages exit 0 *and* no T3 finding; no theme met it), and no report issues NOT-RUN as a per-theme verdict — several T2 page/sample runs were inconclusive (exit 2 / no `summary.md`), but each such theme still has a combined verdict, which is carried through; those incompletenesses are recorded in the findings rather than guessed into a NOT-RUN cell. The report's own verdict word is preserved verbatim inside each findings cell. Cross-cutting items (shared `credit-modal` on samples, `route` preview-notice clipping, 884px/337–419px sample overflow, WebKit CC-badge stray "S", `runtime-hotlink` asset hosts, bblock contrast 1) are called out as such, not attributed to the individual theme.
