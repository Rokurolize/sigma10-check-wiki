# ゴーサインのテスト一式（2026-11-16、主張からの逆算）

## 主張

SCP-JP スタッフのテーマ査読スキル（`theme-component-review`、正本: WSL `/home/roku/src/SCP-JP/claude-plugins-staff/plugins/scp-jp-staff/skills/theme-component-review/`）を全テーマに適用し、**Sigma-10 へ移行しても何の表示トラブルも出ない**ことを確認できたら、ゴーサインが出せる。

「表示トラブル」とは、査読スキル §2 の点検で見つかる表示上の不備のこと： 機械チェック（check_source.py / render_check.py）の error、目視チェックリスト（checklist.md §§1–6、review-points.md §§1–2）で見つかる崩れ・欠落・干渉、ローカライズの型（localize.md 1–11）の当て漏れのうち表示に効くもの、参照 rev 以後に原語版へ入った表示に関わる更新の未反映。

## 母集団

/start のテーマ表の**全行 287件**（実サイト SCP-JP に投稿済みのテーマ44件 ＋ EN・CN・KO 各支部の原典テーマで未投稿のもの243件）。

訂正（2026-11-16 18:32、オーナー指摘）: 初版は母集団を44件に絞っていたが、それはコーディネーターの勝手な狭め方であり、オーナーの「全テーマ」は /start の表にある全テーマを指す。以下の一式は287件全部に適用する（44件分は実施中・一部完了、243件分を追加で実施する）。

各行について：

- 査読対象ページ = テーマ移植候補（正本リポジトリ `pages/theme:<slug>-jp.txt`。行によっては既存 JP ページ＋差分ページの形。その場合は差分適用後の姿が対象）
- 表示確認ページ = 表示確認 Wiki（Wikidot 側 sigma10-jp-test）の `theme-decoration-sample-<slug>-jp`（テーマを include した試験用ページ。checklist §1 は下書きページと試験ページの両方を見る決まり）
- JP オリジナル（Min Theme・Shushuin）は翻訳系テスト（T4・T5）が該当せず、代わりに structure.md の構成確認が入る

## テスト（テーマごとに全部）

- **T1 ソース機械チェック**: `check_source.py <候補ソース> --kind theme --check-links`（翻訳テーマは `--translation` も）。合格 = exit 0（error 0件）。error は全件を指摘一覧に載せ、分類する： (i) 移行時に表示が壊れる → 候補を直す（正本→反映→再チェック）。(ii) 投稿手順の項目（投稿時に scp-jp 側へ書き換える参照等）→ スタッフ適用手順に明記されているかを確認し、無ければ手順側へ書き足す。(iii) 下書きWiki参照（チェッカーの `pseudo-ref` コード）→ 下書き段階では正常な形で、投稿時に scp-jp へ書き換える項目として処置する。注： スキルは当初 sigma10-jp-test を知らず、これらを `hotlink`（直リンク）と誤って分類していた。2026-11-16 にオーナー指示でスキルを編集し、sigma10-jp-test を pseudo-scp-jp と同格の下書きWikiとして明示的に許容した（記録： SKILL-EDIT-20261116.md）。編集前の出力に基づく分類は、ホスト絡みのコードだけ読み替える。
- **T2 表示機械チェック**: `render_check.py` を候補ページと表示確認ページの両 URL に実行（chromium・webkit × PC・タブレット・スマートフォン・320px）。合格 = 両方とも exit 0。横はみ出し・必須要素（評価・フッター・ライセンス表示・翻訳モジュール・トップページへのリンク）・サイドバー開閉・クレジットのモーダル・コントラスト・実行時読込ホストが判定される。注： 候補ページと表示確認ページはプレビュー版クレジットモジュール（credit:start-preview）を使う。プレビュー版はモーダルを開く仕組み自体を持たないため、credit-modal のエラーはテーマの不具合ではなくプレビュー形の性質として処置する（2026-11-16 裁定）。モーダルの実挙動の判定は実クレジットモジュールを使うページでのみ行い、プレビューページではクレジットブロックの静的描画をスクリーンショットで確認する。
- **T3 目視チェックリスト**: checklist.md §§1–6 と review-points.md §§1–2 を、T2 のスクリーンショットとページ実物で上から全部見る。合格 = 表示上の不備が未決着で残っていない。
- **T4 ローカライズの型（翻訳テーマのみ）**: localize.md の型 1–11 を、参照 rev の原語版と突き合わせて1行ずつ判定（当てた／当て漏れ／該当なし）。あわせて `wd_revisions.py diff --from <参照 rev>` で参照 rev 以後の原語版更新を見て、表示に関わる未反映が無いか確かめる（Phase 17/22 の追従記録は先行証拠として再利用し、型判定に触れる箇所は再確認する）。合格 = 表示に効く当て漏れ・未反映が無い。
- **T5 訳文**: 未訳・誤訳・既存 JP 訳との不一致（スキル §2-1.5、checklist §5）。合格 = 表示に出る文言（見出し・使い方・見本・CSS の content:）に未訳・重大な誤訳が無い。

テーマの合格 = T1〜T5 全部合格（指摘は直すか、根拠つきで処置済み）。**ゴーサイン = 287件全部が合格**し、テーマごとの結果台帳（GOSIGN2-LEDGER）がそろうこと（amethyst-v2 は候補自体が作れなかった名前のある例外として、合格数からは除いて明示する）。

## 対象外（この主張には含まれない）

- Wikijump ソフトウェア側の描画の差（PENDING-REMEASURE、issue 群）— 移行は Wikidot 上の出来事であり、この主張は Wikidot 側の確認である。Wikijump の作業はしない。
- 既存記事153件そのものの査読 — 査読スキルの単位はテーマ／コンポーネントであり、記事は対象外。記事の表示は、そのテーマの表示確認ページで代表させる。
