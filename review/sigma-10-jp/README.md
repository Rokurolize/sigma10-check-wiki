## Part 4 — Explanation for a third-party reviewer

### What Sigma-10 is in this repo

Sigma-10 is the JP site theme that real SCP-JP has not yet adopted: production still runs Sigma-9, so the two check wikis are the Sigma-10 *environment candidate* inside which the port candidates are prepared (AGENTS §1, "Two layers"). The environment layer (B) and the per-theme candidate layer (A) must never be conflated; bare 「移植候補」 is banned in campaign writing (AGENTS §1). This row is layer B itself.

`pages/start.txt` is the repo's own description of the environment. L7: "This wiki set is the environment for checking the Sigma-10 JP site theme (the production migration candidate), and each theme row's port candidate is displayed layered on top of this environment." L30: the plain decoration sample with no theme layered on it "is itself the Sigma-10 JP check". L68: "The 'Sigma-10' row is not a theme row; it points at this check environment itself ... That row's 'port candidate' is the plain decoration sample with no theme layered on it (`theme-decoration-sample`)." That is why this row has no sample page of its own: the whole wiki is its display check (LEDGER (d) item 2; RENDER-ROWS-1, RENDER-D row 37 records the sample 404ing with "nothing to verify").

Do not confuse `theme:sigma-10-jp` with `theme:sigma-jp`. The latter is an ordinary EN-origin theme row (rev 16) carrying the Sigma-9 look as a theme: its candidate `pages/theme:sigma-jp.txt` is a Black-Highlighter-framed wrapper with its own CSS. AGENTS §5 "Sigma artifact mapping" records the distinction: the EN-CDN `sigma.min.css` maps to the `scp-jp.github.io/sigma` artifact; `theme:sigma-jp` is a passthrough with no `local--code` delivery; the artifact is what `theme:sigma-10-jp` itself imports.

### How every other package's candidate relates to it

Every other package is a per-theme port candidate that is reviewed as a *layer* on this environment, not as a standalone theme. `pages/start.txt` L36: the check page "@@[[include]]@@s each theme's original-language (or origin-branch) theme page into a page of this check wiki and displays it layered on the decoration sample body under the Sigma-10 JP environment." Concretely, each sample page in `pages/` is a two-line composition — e.g. `pages/theme-decoration-sample-07k-jp.txt` is `[[include theme:07k-jp]]` followed by `[[include theme-decoration-sample]]`. The candidate supplies the theme; the site theme selected on the wiki (this row's candidate) supplies the base. The go-sign claim — that applying the staff skill to all 287 themes confirms migration to Sigma-10 produces no display trouble (AGENTS §3) — is therefore a claim about those layers *as rendered against this environment*, which is why this environment row is part of the population and is counted as passing (LEDGER (b) row 37).

One other candidate, `pages/theme:supply-n-demand-jp.txt` L461, imports the same deployed artifact (`https://scp-jp.github.io/sigma/css/sigma.min.css`) inside its own delivery. That is a theme choosing Sigma-10 as its base — a layer over the environment — not a second environment row.

## Strain the K2 case puts on the package format

Three places where the standard format does not fit this row; each is reported rather than forced:

1. **The diff slot has no port diff to hold.** `build_review.py` generates `diff.md` for any directory holding `original.txt` and `candidate.txt`, so this package has a diff file. Its content is a 27-line instruction page against an 8-line import wrapper — unlike objects — and Part 3 disclaims it rather than presenting it as a port diff. The generator's Tier-1/Tier-2 presentation and the classification templates all assume an original-to-port relationship this row lacks.
2. **The classifier's signatures fire on the wrong mechanism.** With one whole-file block, `classify_hunks.py` labels it `ANNOTATION` (the header comment), `DELIVERY-HOST` (host change on the `@import`), `EXHIBIT-RESTRUCTURE` (a code block replacing a code exhibit in the mirror), and `SELF-DELIVERY` (the `sigma.min.css` URL matched as a code-delivery reference). None is a real port change. `classification.json` is kept for format completeness but is explicitly not evidence; the explanation is hand-written in this README.
3. **"7-line" vs "8-line" wrapper.** SPECIAL-ROWS K2 uses both phrasings. The measured file is 8 lines / 486 bytes; this package follows the bytes and records the discrepancy (Part 2).

None of these is a defect in the campaign record or the candidate; they are consequences of giving the environment's own row a package shaped for ported themes.
