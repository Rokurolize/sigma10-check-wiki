# AGENTS.md — working rules for this repository

This repository holds the canonical sources for the SCP-JP Sigma-10 theme migration candidates and their display-check composition. If you are an agent (OpenCode lane or Muse) opening this repo to work on the migration, this file is the campaign's consolidated rule set: every rule here exists because its absence already cost time or correctness. The procedure itself lives in the theme-component-review skill (§2) — this file does not repeat it; it carries the campaign-specific adjudications, exceptions and process rules that modify or supplement it. Where this file and the skill's generic text conflict, this file governs campaign work; report the conflict instead of silently picking one.

## 1. What this repository is

- **Canonical source of truth.** `pages/<fullname>.txt` is the canonical text of each page. The review target for a theme row is its candidate source `pages/theme:<slug>-jp.txt` (for rows in existing-JP-page + diff-page form, the post-diff applied shape). Edits anywhere else (lane copies, live wiki pages) do not count.
- Canonical text is the Wikidot-side text. The Wikijump side is the same text after the ALLOWLIST.md A1/A2 transforms (which apply only inside `theme-decoration-sample`), plus at most a trailing-newline difference.
- **Two layers — never conflate them.** (A) テーマ移植候補: a per-theme JP port, `theme:<slug>-jp`. (B) The environment layer: real SCP-JP still runs Sigma-9, so the check wikis are the Sigma-10 *environment candidate* inside which (A) is prepared. Bare 「移植候補」 is banned in campaign writing; name the layer.
- **Check wikis (both are mirrors of this repo):** Wikidot `sigma10-jp-test` — the sanctioned draft host, same status as pseudo-scp-jp; a theme's display-check page there is `theme-decoration-sample-<slug>-jp`. Wikijump stafflab site 6000303 (`scp-jp-sigma10`) — the Wikijump-side check wiki. Render/check work grades against these pages and this repo, nothing else.
- **Environment working base.** The environment candidate's site theme is served from the fork `https://github.com/Rokurolize/sigma` (fork of SCP-JP/sigma): sigma10-jp-test imports its GitHub Pages stylesheet `https://rokurolize.github.io/sigma/css/sigma.min.css`, and the fork's push-triggered Pages deploy is verified working (2026-11-08). Base all future Wikijump-side Sigma-10 port work on that fork — not on SCP-JP/sigma (org repo, staff review-gated; §4 fork base) and not on the superseded KanekoLiku base snapshot kept in the campaign archive.
- **Original-theme check-page companion includes.** A display-check page for an original theme is built as companion include(s) FIRST, then the theme's own include, then `[[include theme-decoration-sample]]`: ten BHL-family themes (aesthetic-theme, extra-black-highlighter-theme, hansarp, isolated-terminal, jakstyle, minimalist-bhl, ouroborous-theme, redtape, scp-offices-theme, sigma) put `[[include theme:black-highlighter-theme]]` first; skipos puts `[[include theme:bedrock]]` first; inkblot's own include carries a parameter: `[[include theme:inkblot accent=transparent]]`. Rebuilding one of these check pages in the default single-include form reproduces a wrong page.
- **Population = all 287 /start theme rows** (44 posted on real SCP-JP + 243 unposted EN/CN/KO originals). Never scope a sweep to the 44 alone.
- **Repo files ≠ population.** The repo holds 287 `theme:*-jp.txt` files, but `theme:creepypasta-jp` and `theme:pacom-jp` are dependency base themes referenced by /start rows, not rows themselves; the /start row `theme:quand-le-soleil-se-couche` has no `-jp` suffix (its canonical name is unsuffixed); `telecommunications-monitoring-office-theme` is listed in /start under a shortened name — the candidate is `theme:telecommunications-monitoring-office-theme-jp`. Reconcile by identity, not by filename pattern.
- **Original wikis:** EN `scp-wiki.wikidot.com`, CN `scp-wiki-cn.wikidot.com`, KO `scpko.wikidot.com`. (`scp-wiki-ko.wikidot.com` does not exist.)
- **Prior art first.** The scp-wiki-translation repo already holds Japanese files for 220 of the 243 Stage-2 themes (index: campaign record `PRIOR-ART-INDEX.md`; 23 absent), and the campaign's `PATTERNS.md` defines the 8 mechanical patterns for bringing a prior translation to campaign form plus 3 judgment residues. Do not re-translate from scratch what exists in reviewed JP form.
- **Campaign records** (reports, rulings, ledger parts, commit-wave partitions) live in `/home/roku/.local/state/wikijump/muse-bhl/theme-port-readiness-20261114` ("R" below). Deliverables go there, nowhere else.
- **Judge from this repo.** Saved sweep grades and /start strings can be factually wrong (a prior sweep recorded 8 themes as "no port candidate exists" whose files were all present). Repo reality overrides inherited strings; when a brief's premise contradicts the files, follow the files and record the discrepancy in your report.

## 3. The tests, as this campaign applies them

**The claim under test:** applying the staff skill to all themes confirms that migrating to Sigma-10 produces no display trouble. A theme passes iff T1–T5 all pass, with every finding either fixed or dispositioned with grounds. Out of scope for this claim: Wikijump-side rendering differences (write 「Wikijump側の描画の差」, never the ambiguous 「プラットフォーム」), and the 153 existing articles themselves (represented by their themes' display-check pages).

### T1 — source check

- Command per §2. Pass = exit 0, zero errors. **Every** error is listed and classified exactly one of: **(i)** breaks display at migration → fix the candidate (canonical → reflect → re-check); **(ii)** posting-procedure → rewritten/re-hosted to scp-jp at posting (confirm the posting procedure says so); **(iii)** draft-form → the candidate's own `local--code` on the draft host, sanctioned at draft stage. Tie-break: torn between (i) and (ii) → choose (i) and say why — with one settled exception: `http` → (ii), below.
- Class table (checker code → disposition):
  - `pseudo-ref` — draft-host reference. → (ii) posting rewrite to `scp-jp.wdfiles.com`. Never "fix" it in the candidate.
  - `hotlink` — host outside the allowlist. By sub-case: own `local--code` on the draft host → (iii); own attachments on the draft host (`local--files/<own fullname>/…`) → (ii) re-upload + rewrite at posting; cross-page draft-host reference (another candidate's files) → (ii) (class (iii) is *own* code only); outside hosts that serve today → (ii) re-host to SCP-JP storage / exception-list CDN at posting; dead or placeholder → (i), see dead references below.
  - `foreign-include` — all classed (i), including inert escaped examples (checklist §4 covers code examples in usage sections). Fix iff a verified JP counterpart exists (§5); otherwise leave byte-unchanged as a named exception. Never invent a JP page.
  - `http` — → (ii) scheme rewrite at posting. Right host/file serving over both schemes is not a candidate defect; do not edit.
  - `unencoded-colon` — → (i), fix in candidate: encode only the path-segment colon(s) to `%3A`, gated on a redirect-following HEAD 200 for the encoded form. In scope: page-name segments (most real cases), not only `file:<id>` segments. `@@…@@` escaped text is exempt; CSS `/*…*/` comments are NOT exempt. If the encoded form does not serve, do not encode — leave flagged and report (5k L94 precedent). Unflagged occurrences are left alone.
  - `credit-missing-fields` — → (i): add only the missing fields of the eight (§4 ruling 3), values evidenced, never invented.
  - `no-credit` / `no-rate` — → (i): add `credit:start-preview` (it is rate-bearing; see the Rate rule in §5).
  - `old-bhl` (EN BHL delivery host `nu-scptheme.github.io`) — → (ii); rewrite target is `scp-jp.github.io/Black-Highlighter`. Fix lanes leave it untouched.
  - Warnings (`link-target-missing`, `link-label`, `interwiki-touched`, …) are recorded verbatim, not classified or fixed — except `no-interwiki-style`, which the fix waves DO fix (pattern 6, §5). Self-references to not-yet-posted `theme:<slug>-jp` inside `link-target-missing` resolve at posting.
- **Dead-reference evidence standard.** For every suspect URL: (1) compare against the branch original today at its current revision (fetched once, rev + `updated_at` recorded); (2) hunt the asset's real home in the original's own file list / the author's wiki / hosting named in the original source, validated by HEAD/GET with content checks; (3) if no serving source exists there — no upload, no substitute, leave byte-unchanged, record ORIGINAL-DEFECT. Repoint only on sameness evidence (exact filename + identical usage; the original's own file list containing it). Archive snapshots are not a home; a different-colour variant is not the same asset. Probe protocol for timeouts/429: HEAD → GET → descriptive-UA GET; serving under any pass = serving. Verify "dead" links at the complete, untruncated URL (parentheses included) before dispositioning. A `hotlink` error surviving a repoint means "host still needs posting-time re-hosting", not "still dead" — the checker has no dead-link code.

### T2 — render check

- Run `render_check.py` on BOTH the candidate-page URL and the display-check-page URL, chromium + webkit × PC / tablet / smartphone / 320px. Pass = exit 0 on both. Exit codes: 0 = no errors; 1 = ≥1 error (with `summary.md` + `result.json`); 2 = page could not open. A crash traceback also exits 1 but writes no `summary.md` — distinguish by the file's presence. T2 non-completion is a network/server disposition, never BLOCKED-ENV.
- **Credit-modal preview rule (adjudicated 2026-11-16).** Candidate and sample pages use the PREVIEW credit module (`credit:start-preview`); the test wiki replaces it with the preview notice and it has no modal-opening mechanism at all. A `credit-modal` error on such pages is a property of the preview form, uniform across themes — **never a theme defect, never a fix target**. Judge real modal behaviour only on pages using the real credit module; on preview pages verify the credit block's static rendering by screenshot. Never modify checker scripts to force the modal. (Distinct and candidate-inherent: page-side credit-modal *overflow* at ≤375/320px on real-module pages IS a theme defect.)
- **Environment-layer lines — record, never charge to a theme:** `runtime-hotlink` hosts `rokurolize.github.io`, `rsms.me`, `scp-wiki.wdfiles.com` (they come from the site theme's `sigma.min.css` @import — the Rokurolize/sigma fork's Pages stylesheet, §1 — not candidate code — candidate-own runtime hosts are recorded verbatim as judgment-required); site-header subtitle doubling at ≤375px (environment-layer; one conflicting attribution is open, §9); preview-notice row clipping/overprint at ≤375/320/768px (wiki preview chrome); sample `page-overflow` from the static credit replica's fixed width (shared sample construction); WebKit's stray "S" glyph for the CC badge in the credit modal / §30 replica (engine quirk); a capture whose only hotlink host is `http.cat` with a block of `hidden-*` errors = a transient Wikidot 503 page, not a result; deliberate specimens (`hl-code` long lines, `bblock`/`dblock` contrast 1, `wiki-content-table` overflow) are by-design; `sidebar-position` warn = JP position vs the Sigma-9 baseline; `hidden-rate` where the source has no `[[module Rate]]` is correct machine behaviour; the `url-https//…` interwiki-frame stylesheet 404 comes from shared `styleFrame.html` infrastructure.
- **Candidate-inherent T2 defect classes** (charge to the theme): fixed min-width `page-overflow` on candidate pages; narrow-width header clipping/collision; interwiki-style port defects (duplicate `priority=1`, missing `priority`, double include); dead/malformed resources in candidate CSS (`url(null)`; Google Fonts @imports with hyphens for `+` — HTTP 400, fonts never load; unquoted font-awesome @import — Wikidot's pipeline rewrites it to a 404, broken as authored on any Wikidot; assets served `text/plain` — a Chromium ORB-block vs a WebKit 404 for the same file is one defect, not two); unsubstituted include variables rendered literally; a theme pinning the static credit replica `position: fixed` at viewport centre.
- **Blank-body caution.** If a candidate body doesn't render, check the test-wiki page's tags first: pages carrying tag `theme` instead of `テーマ` make `[[iftags +テーマ]]` bodies never render — that is test-wiki page state, not candidate CSS. Generally: rendering that contradicts the canonical source = possible stale static cache, not a defect, until re-checked.

### T3 — visual checklist

Walk checklist.md §§1–6 and review-points.md §§1–2 from the top, against T2's screenshots AND the actual pages, on BOTH the candidate (draft) page and the sample (test) page. Pass = no display defect left unresolved. Screenshot discipline is in §7.

### T4 — localize patterns (translated themes only)

Judge localize.md patterns 1–11 line-by-line against the original **at the reference revision** (APPLIED / MISSED / N-A, line-number evidence in every cell), and run the follow-up diff (§5 for the exact invocation). A row fails the follow-up half only if a post-reference-revision hunk of kind `css_rules`/`css_vars`/`includes`/`scripts`/`body_text` is unincorporated AND display-affecting; `fonts`/`body_url_only`/`import_url` (AutoLocalize) moves are not followed. Phase 17/22 records cover the 44 Stage-1 rows only — they contain no dispositions for Stage-2 slugs; do not re-derive that absence per lane. The recurring defect shapes are the pattern list itself; the campaign's settled applications are in §5/§6.

### T5 — translation text

Pass = no untranslated or seriously mistranslated **visible** text (headings, usage text, samples, CSS `content:` strings). EN in-universe proper nouns (UIU/FBI, SPC DATABASE, GoI names) are intentional residue — not findings. Plain `翻訳責任者` wording and 元記事リンク link text other than the 原題 are a once-per-report uniform nit, not per-row failures.

### JP-original themes

Min Theme and Shushuin are JP originals: T4/T5 do not apply; the structure.md composition check applies instead. Their recorded state is "no reference revision (JP original, no follow-up target)" — never 「基準不明」. Checker runs on them omit `--translation` (§5).

### Retired

Check 5 (per-sample interaction measurement) is **retired** for Stage-2 integration — never re-run it per sample. Its defect class was root-caused to a hand-written exhibit in the shared sample body (fixed in Phase 20); the cause is settled.

### Verdict vocabulary

Per theme: PASS / FINDINGS (list) / BLOCKED-ENV (exact missing-executable path) / EXCEPTION (no candidate or sample exists). Classification legend for findings: Candidate-inherent / Environment-draft-form / By-design. Environmental failure is expressed per-theme, never as a BLOCKED completion line.

## 4. Owner rulings and standing orders

### The five rulings of 2026-11-16 (RULINGS-20261116.md)

1. **Cross-theme delivery.** A dependent theme imports the base theme's **JP port candidate delivery**, never the original branch's delivery as-is — a base (e.g. Basalt) cannot be used as-is in the Sigma-10 JP environment; its candidate carries the fixes, and re-applying them per dependent is rejected. Procedure and exceptions: §5/§6.
2. **Header/title language is out of scope.** Whether `--header-title` etc. stays English is translation taste, case-by-case; English can be design-correct. Never change it, never flag it as a defect, in either direction. Pattern-9 findings of this kind are disposition-only in the ledger. (Finding test: a plain English sentence/slogan counts as a pattern-9 finding to disposition; a proper-noun-only brand mark is noted, not failed.)
3. **Attribution (TASL).** All CC BY-SA 3.0 material carries Title, Author, Source (the original URL — a reference revision number is NOT a Source), License (name + link); adaptations are noted as adaptations. Translator attribution: a translation by Muse or its delegated agents is 翻訳責任者「AI」; human translator names stand only where they match the live JP page's `created_by`. A candidate modifying someone else's existing translation carries the line 「**翻訳について:** <name> による既存の翻訳を基に改変したものです。」 Credit completeness is measured against localize.md §3's eight items （タイトル/翻訳責任者/翻訳年/原題/著作権者/作成年/初訳時参照リビジョン or 改訳時参照リビジョン/元記事リンク）, with §3 name normalization （著作権者 not 著者; 元記事リンク text not 「ソース」; 原題 not hyperlinked). Field values come from evidence (the fetched original + `start.txt` reference rev); where evidence is missing the honest state is BLOCKED-DATA, never invention. A repo-level TASL attribution record is owed before any PUBLIC upload of this repo.
4. **Components port with their theme.** A component/fragment a theme needs is ported as part of that theme's work. "Blocked while the component is missing" is rejected. Canonical already carries `component:sigma-plus-jp`, `component:betterbetterfootnote-jp`, `component:navla-jp`, `component:rok-gov-base-jp`, `component:the-buck-stops-here-base-1-jp`, `component:license-box-theme-jp`. Dependency completeness is a ledger check (§6, DEPS classes).
5. **Credit modal.** The owner left the Basalt sample modal failure undecided; the coordinator's investigation root-caused it to the preview form (§3, T2 rule). Do not re-open it as a theme defect.

### Go-sign standard vs /start picture (owner, 2026-11-16)

The go-sign condition is the staff-skill sweep over all 287 themes (the §3 claim). The "/start completion picture" (Wikidot-side materials complete; Wikijump-side differences recorded with issue numbers) governs only what /start lists as remaining work — it is NOT a go-sign basis; a go-sign issued on it was withdrawn the same day. /start's remaining work is Wikidot-side only; a row differing only on the Wikijump side is finished for /start once the difference is recorded with its issue number. Derive verification backwards from the claim actually being made; never substitute a weaker neighbouring standard.

### Standing orders binding lane work

- **No asset re-uploads on the check wikis** (2026-11-16). Image/asset references stay as direct links to their original hosts, even where a skill text says otherwise. Draft-bucket asset 404s are a campaign-wide deferred condition (uploads owed before posting), never a per-theme defect or completion blocker. (The older "store the image in Wikijump and rewrite the source" ruling applies to Wikijump lab display tests, not check-wiki re-hosting.)
- **Include-prefix working rule.** Working deliverable sources use the bare form (`[[include component:...]]`); the `:scp-jp:` prefixed form is the staff-recommended final form at posting, not the working form. Context forms: §5.
- **Fetch discipline.** Wikidot access is pre-approved standing policy: fetch each original once, cache it, reuse the cache; keep accesses minimal even at the cost of extra local trial-and-error. Never fetch the same page twice; never stop work to ask approval for a fetch.
- **Sandbox probe pages are kept**, never deleted: leave `muse-probe-*` pages in place (distinct names where needed, overwrite-reuse where possible) and list them in your report — they are the permanent viewable record of live behaviour.
- **Stage-2 candidates include a Japanese translation of the theme's accompanying documentation** — decided; never list it as awaiting judgment.
- **Original's technical mistakes:** if the EN/CN/KO original has a technical mistake, the JP port fixes it and records precisely where and what kind, so it can be reported to the original's author. A theme not yet published on SCP-JP being a lab target is normal — never frame it as an anomaly.
- **Priority:** existing scp-jp articles outrank port candidates; existing pages are what breaks on migration day.
- **Design reference:** EN-origin themes are designed around the info module, not JP's credit-with-rating module; the info module's decoration is the reference for intended credit-module styling, JP localization code supplements the credit module to fit the theme naturally, and the theme-decoration-sample must cover the info module.
- **Wikidot behaviour is definitionally correct** in parity questions: if live Wikidot produces an observable behaviour it is the spec, however malformed — no "both sides are pathological" category, no native-improvement carve-out. Never leave a divergence undecidable for lack of a live example: create the example on live Wikidot.
- **Fork base:** changes to SCP-JP org repos need other staff members' review, so theme/port work is based on forks under Rokurolize.
- **Autonomy:** newly discovered problems are part of the remaining work, not a reason to stop and ask. Proceed; record decisions and their grounds in the report.

### The Rate-module rule

`credit:start-preview` is rate-bearing. Therefore:

- Preview module present + a bare live `[[module Rate]]` beside it → **duplicate = defect: delete the bare one** (two rating widgets render on the page today).
- No credit module at all → add `credit:start-preview`; add a bare `[[module Rate]]` only where no preview module will exist.
- **Labelled-exhibit exception:** a deliberately *labelled, paired* exhibit stays (precedents: Classic, monotypical, flopstyle-dark, shark-punching-centre-bhl's 評価：/クレジットモジュール付き評価： pair). The checker's `double-rate` info is this same shape — judge by labelling, not by the hit. Escaped or tag-gated `double-rate` hits are false positives.
- The preview-vs-plain form itself is left alone where out of scope (pataphysics keeps `credit:start`, warn only); credit fixes keep each candidate's existing prefix style verbatim.

### Translator attribution — settled mechanics (ruling 3 applied)

- Campaign translations: 翻訳責任者「AI」, 翻訳年 from evidence. The earlier sibling convention (campaign-new pages get 翻訳責任者「SCP-JP」/翻訳年 2026) is **superseded — never reintroduce it**.
- Where `start.txt` records only a 改訳 revision, write that revision also as 初訳時参照リビジョン and keep the 改訳 line (settled practice, flagged as policy in reports, not evidence).
- Structural/delivery deltas (includes, credit furniture, iftags, CSS delivery, URL re-hosting, `[[*user]]` → plain markup) do NOT trigger the TASL adaptation line; text-level changes do. Borderline precedent: foxtrot's ~35 `@@［画像:…］@@` placeholders judged not a text-level modification (asset-availability family) — no adaptation line.
- Authorship edges: a fork's 著作権者 is the fork author where the page asserts the fork in its own header; dual 著作権者 is allowed from license-box `author=` + header credits beyond `created_by` alone; a deleted account's `created_by` returning `?` is resolved from the page body's own attribution line (named in the page, not invented) and is not BLOCKED-DATA.

### Interwiki-style (pattern 6) fix form

Add `:scp-jp:component:interwiki-style` where absent — without it the translation-module frame never renders. Priority discipline: own code = 1; BHL-family rows additionally normalize=1 / BHL=2 / own=3, split top/tail where the tag gate intervenes, per named siblings. Variants with a single priority=1 or an omitted `priority=` are findings, not passes. Insert before the first `[[iftags +テーマ]]`, `theme=` = own draft-host code. Where the theme's CSS is inlined and no code file exists, include with neither `theme=` nor `css=` (pointing at a nonexistent file is a broken reference); a `theme=` pointing at a `local--code` URL that currently serves a placeholder is correct — the code page materialises at posting.

### JP fonts (pattern 7) and font hosts (pattern 5)

A ledger/extraction scope ("data extraction only — edit nothing, reflect nothing") overrides any fix-lane boilerplate copied into the same brief (canonical-first edits, checker re-runs, reflect steps). Do not re-run checkers or renderers for extraction unless the scope itself says so; copy the existing outputs, copy each report's verdict word verbatim rather than splitting a joint verdict, and state that rule in the deliverable.

### Brief-writing conventions (for whoever writes the next brief)

Ownership line, verbatim, in every brief: "This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it." Scope positively — order the work that is in scope; do not pad with prohibitions of out-of-scope work. Every named tool or script carries its local absolute path (clone/fetch referenced external repos to a durable local path before dispatching). Write long briefs in ≤~3.5 KB chunks and read back the brief's TAIL on the destination before launch — a byte-size check verifies transfer, not content, and a truncated tail (scope/gates/constraints replaced by a "[truncated N chars]" marker) has already shipped once. ## 7. Process rules

- **Canonical-first.** Edit the canonical file → re-run the checker on that file → reflect to BOTH wikis → verify. Never edit a wiki page directly to fix a defect; never edit page content to hide a defect. Integration order per batch: canonical copy → /start splice → single canonical commit → reflection to both check wikis → scoped verification → report.
- **Checker re-run per edited file:** the targeted code goes to 0; residuals are named as another lane's scope or a sanctioned class. Credit fixes are additions-only — no existing line rewritten or deleted (verified by git diff).
- **Reflect route (exact):** `cd /home/roku/.local/state/wikijump/muse-bhl/theme-port-readiness-20261114/stage2-lanes/lane-oc-rework2-int/work && /home/roku/src/Rokurolize/wikidot.py/.venv/bin/python reflect_one.py <fullname> edit`; for new pages, the same route with `create --title '<title>' --tags '<tags>'`, mirroring the original page's title/tags. Audit before creating (§5): CREATE is refused for an existing page.
- A page counts as reflected only when both sides print `edited` and the run ends `REFLECT_DONE`. Reflect `edit` preserves the existing wiki title/tags — wrong live titles persist through reflect; flag them, don't expect reflect to fix them. Wikijump `page_get` returns `wikitext: None` for every page in this environment, so read-back via page_get is inconclusive by nature: a WJ edit is proven by `revision_number` increment plus the `Stage 2 REWORK2 integration` comment reflect_one.py writes.
- **Whole-file reflect hazard.** `reflect_one.py edit` pushes the entire working-tree file, including sibling lanes' uncommitted hunks in the same file. Disclose in your report any sibling hunks your reflect pushed. Before reflecting, check whether another lane is concurrently editing your files — the credit-D / fix2-credit overlap silently shipped pre-edit versions of 36 files to both wikis, a drift visible only by cross-lane timing reconstruction.
- **WJ lock remedy.** On a Wikijump-side `FAIL no lock` ONLY: move `~/.local/state/wikijump/muse-bhl/sigma10-unify-20261114/.session.json` aside once (suffix per wave: `.stale-fix`, `.stale-fixd`, `.stale-fixp4`, `.stale-fix2`, `.stale-fix3`) and retry once. Caveats: the move overwrites a prior lane's same-suffix backup (the evidence trail is single-slot — note it in your report); one retry is not always enough — unrecovered pages are reported as coordinator re-run items, never hidden (fix2-colon: 4 left; credit-D: 69 left).
- **`result: null` is NOT a lock failure.** The `.session.json` remedy does not fix it and must not be applied to it — including a first-pass `result: null` that was never a `no lock`. Prove the end state read-only instead (revision increment; SHA-256 of the WJ wikitext byte-identical to canonical where retrievable) and report the pages as coordinator re-run items.
- **Verification.** Batch closings use `verify_scoped.py` (in R) with page fullnames as CLI args; success line `SCOPED-OK: <n> pages match on both wikis`. **Never run full verify.py inside a batch or integration** — campaign-final only (full runs consumed ~65% of measured integration wall-clock). verify.py is incremental since 2026-11-16 (one Wikijump query for all pages; Wikidot fetches cached behind canonical-hash/updated_at probes; warm re-run ~23 s vs ~36 min); the one page whose name is too long for the page-list sweep has no updated_at probe and is refetched on every warm run — expected, not a bug. A verification script that refetches everything on re-run is unacceptable by design.
- **Drift discipline.** The drift set is re-established from verify output only — never from lane-reported lists (lanes reported 74 drifted pages; verify_scoped's primary evidence found 97). Re-reflect only proven-drifted pages, re-verify clean, and only then does the commit gate open.
- **Commits.** Lanes reflect but never commit. The supervisor commits, per fix wave, re-partitioning the file sets at commit time (lanes add modified files meanwhile; a stale partition misattributes files). Canonical commits are part of the work — do not hold finished work uncommitted pending owner judgment; a commit alone publishes nothing. Publication is separate: the private GitHub repo `Rokurolize/sigma10-check-wiki` is approved for distribution (VM clone at `~/workspace/sigma10-check-wiki`); public upload waits for the TASL record (§4).
- **/start updates:** canonical repo first, wiki reflection after, on each integration advance; the coordinator reviews each update herself.
- **/start theme table is split and generated (2026-11-17).** `pages/start.txt` is now a hub (~13K chars); the 287 theme rows live on seven subpages (`start:themes-stage1`, `start:themes-en-1..3`, `start:themes-cn-1..2`, `start:themes-ko`) generated from `start-themes.tsv` by `build_start.py`. A /start splice now means: edit the TSV row, run the generator, commit TSV + subpages + hub together, then reflect `start` and the touched subpages. Never hand-edit a `start:themes-*` file, and never insert a blank line inside a generated table (Wikidot splits the table there). `build_start.py --check` is the gate. Row order inside Stage-2 subpages is sample-slug order; the integration wave stays recorded in each row's 「整備」 field.
- **Oversize rule.** Never inline base material (frameworks, shared base CSS) into a candidate page. Mirror the original's file separation: the base lives in its own include-target page (`theme:parallel-jp`, `fragment:peroxide-jp-base-css` / `-elements-css`) or an external @import; the candidate carries only its own CSS. Four candidates exceeded the 200,000-char limit this way (betwixt, kitchen, peroxide, magazine) and had to be restructured.

Body: per-theme verdicts with line-number evidence for every claim ("no evidence, no finding"); totals that sum exactly, stated as machine-extracted from the `out/` files; a "deliberately left, with grounds" section; reflect failures quoted verbatim incl. - **Screenshot/media discipline.** At most 2–3 screenshot images per tool call; prefer text outputs. Never open a raw `full.png` (sample pages run 20,000–31,000 px tall; Chromium also white-outs past the 16384/32767px capture cap) — slice it: plain `python3` on the box has no PIL, use `uv run --with pillow python`. Fall back in this order: respawn on a different worker type (a free-model worker), or do the work in the root session. Never just wait for the limited pool — no lane that waited recovered. Also: do not burn turns in content-free "waiting…" loops while background jobs run; check the job's state, then act on it.
- **Render drivers.** Skip targets that already have `summary.md` — a driver restart (e.g. after the WSL reboot) resumes instead of redoing completed runs. Wrap every attempt in a shell `timeout`: a render_check worker alive for hours at ~0% CPU is hung (leaked browsers from timed-out runs) — kill the tree and re-run just that target; never wait indefinitely. Separate deterministic failures (identical failure ×3 — stop retrying; e.g. deterministic screenshot-oversize, per-engine networkidle failure at every width, T3 then Chromium-only with auxiliary captures labelled non-official) from flaky ones. After killing a driver, sweep its orphaned render processes — and kill via a script file, because a `pkill` pattern can match the killer's own command line.

After sending a prompt, verify the turn actually started (pane footer "esc interrupt" = working); under load, prompts land as unsubmitted "[Pasted ~1 lines]" composer text (fix: pane send-keys Enter) or are eaten by overlays. Judge a lane's state from pane text and processes, not from agent_status alone (herdr has reported "working" for a usage-limit-dead lane).
- **Shared box.** The WSL box is shared and memory-bound (24 GB RAM / 16 GB swap / 16 CPUs since 2026-11-17): stagger render_check browser batches to at most 2 concurrent. If swap thrashes, SIGSTOP-pause the swing batch (its `out/` state persists and the lane is unaffected) — do not kill lanes. ## 8. Toolchain traps (paid for already)

- **render_check.py baseline cost.** The stock script navigates with `page.goto(url, wait_until="networkidle", timeout=90000)` hardcoded, no env override, up to 2 gotos per viewport × 8 viewports. One run is ~2.5–3 min healthy and up to ~25 min when timing out — and the dominant failure point is the baseline page (`https://scp-jp.wikidot.com/custom-theme-policy`), not your target: targets return 200 in ~1 s via curl while Playwright `networkidle` times out on the ad-heavy baseline. Parallel launches make it worse (a parallel-4 first pass completed 25/60 runs; sequential retries completed the set).
- **Lane-local render variants are lane-local.** A lane copy of render_check.py with `wait_until` → `load`, a once-captured reused baseline (`render_check_cached.py` / `baseline_cache.json`), or force-click patches for overlay-intercepted clicks (`render_check_forced.py`, plus tolerance for failed sidebar/credit interactions so a summary is still produced) can make a check completable — the `load` variant needs a 600 s per-run timeout, not 300 s. These live in the lane dir and are **not precedent**: never modify the skill's checker without a coordinator ruling. A lane-local `PLAYWRIGHT_BROWSERS_PATH` pointing at a lane-owned browser copy is the no-collateral recovery when the shared bridge breaks.
- **Playwright bridge symlinks are shared fragile state.** Launches depend on symlinks in `~/.cache/ms-playwright/` (`chromium_headless_shell-1194 → -1248`, `chromium-1194 → -1248`, `webkit-2227 → webkit-2370`; the skill pins Playwright 1.56.0, which has no Ubuntu 26.04 build). A WSL restart wipes them; another lane's `playwright install` can delete them mid-run under a live driver. (Stage-1 briefs cited `webkit-2215` — stale.)
- **The 200,000-char limit masquerades as lock/captcha failure.** An over-limit save returns a generic `status: "error"` and was misread three ways (`TargetErrorException: Page … is locked or other locks exist`; an AMC error; a need_captcha hypothesis). Read the save body: `ページソースが長すぎます(最大200000文字)`. The locks observed in that incident were the tool account's own probe locks, self-expiring — not a posting-path block.
- **Wikidot source normalization causes phantom drift.** On save, Wikidot strips a leading blank line (LF) and converts leading tabs to 4 spaces. Canonical files must match that normalization; when verify reports drift of exactly this shape, normalize the CANONICAL file and re-reflect (precedents: canonical commits a393736, 3607153) — never edit the wikis to match.
- **Checker/link fragility.** `check_source.py --check-links` makes live httpx requests; one `ConnectTimeout` can abort a whole sweep (a 286-check run died at 168 outputs with no results file) — use a resumable runner: parse the valid existing outputs, run only the missing checks, retry transient failures. `wd_revisions.py source scp-jp <page>` intermittently returns HTTP 503 for pages that exist — `sleep 3` and retry. Fetch timeouts generally: retry only the failures and merge (13 of 396 existence fetches timed out once; re-fetching only those ended at zero errors).
- **wikidot.py API shape.** `Page.source` is a `PageSource` object, not `str` (`f.write(page.source)` raises TypeError; it has no `.splitlines`). `Page` has no `.history` attribute — use `latest_revision`, `revisions`, `created_by`, `source`, `files`. Multiple lanes burned sessions re-discovering this.
- **Existence probes.** Judge by HTTP status, not title (a scp-jp 404 still returns the generic title `SCP財団`). Follow redirects — malformed targets (trailing-`@@` artifacts like `theme:foxtrot@@`) normalize to the real page.
- **Extraction traps.** URL extractors that truncate at parentheses manufactured false dead references (the White_on_White case, §3). A `credit:start\b` regex matches `credit:start-preview` and overstates plain `credit:start` usage. Include-scan regexes miss some `[[include]]` forms — validate any counting method against known reference counts before trusting its output (the deps scan iterated four schemes before reproducing 195/198 reference counts).
