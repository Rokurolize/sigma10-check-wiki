# Formal verification of sigma10-check-wiki

This repository's promise is that its review record never lies about the bytes it
describes. That promise is implemented by machinery: `review/build_review.py`
(package generation and verdict stamps), `review/sources.tsv` (hash-pinned
provenance), `build_start.py` (the /start index, generated from structured
rows), `patterns/build_index.py`, and `review/lint_patterns.py` (the patterns
knowledge base as executable lint). This directory proves, in two layers, that
the machinery keeps the promise and that the current tree satisfies it.

## The six invariants

- **I1, stamp truthfulness.** A package's verdict stamp reads PASS only while
  its candidate still byte-equals the canonical page and is unchanged since
  the ledger verdict it cites. A changed candidate stamps STALE, never a
  fresh PASS.
- **I2, diff fidelity.** Every `diff.md` is exactly the generated diff of the
  `original.txt` and `candidate.txt` it sits between (two named exceptions,
  below).
- **I3, mirror integrity.** Every `original.txt` hashes to the `mirror_sha256`
  pinned in `review/sources.tsv` for its recorded revision. Mirrors are
  write-once; no maintenance action rewrites one.
- **I4, /start consistency.** Every /start row resolves to a review package,
  and every theme package is reached by a row. /start is generated from
  `start-themes.tsv`, never hand-edited.
- **I5, coverage accounting.** Every pattern (KB-01..KB-81) and every negative
  ledger entry (NL-01..NL-15) is dispositioned exactly once by the lint
  coverage ledger, and the ledger agrees with the linter's own rule and
  suppression structures.
- **I6, candidate sync.** Every package's `candidate.txt` byte-equals its
  canonical page in `pages/`.

## Layer 1: the protocol, in TLA+

`SigmaReview.tla` models the maintenance protocol (page edits, candidate
syncs, package regeneration, ledger verdicts, commits) over two packages and
proves I1, I2, I3, and I6 over every interleaving of those actions, over
committed states. TLC result for the true protocol (`SigmaReviewTrue.cfg`):
no error found; all invariants hold. Full output: `results/SigmaReviewTrue.out`;
the spec report with the machinery-to-model mapping is `SPEC-REPORT.md`.

A check that has never failed proves nothing, so four broken variants each
remove exactly one guard, and TLC catches each one:

| Variant | Guard removed | Invariant violated | Counterexample length |
|---|---|---|---|
| StampNoCompare | the stamp's changed-file compare in `assemble_stamp` | I1 | 5 steps: edit, sync, regenerate stamps PASS citing the old hash, commit |
| MirrorRecopy | original immutability | I3 | 6 steps |
| RegenSkip | the commit-time regeneration guard | I2 | 4 steps |
| SyncSkip | the commit-time sync guard | I6 | 3 steps |

Raw outputs: `results/SigmaReview<Variant>.out`. Read any TLC trace with the
pstack `/statechart` skill, which renders invariant violations as shortest
paths in plain words.

## Layer 2: the current tree, byte for byte

`audit_repo.py` (stdlib only) checks all six invariants against the actual
tree, importing the machinery itself (`build_review.assemble_stamp`,
`build_review.generate`, `lint_patterns.RULES`/`SUPPRESSIONS`) rather than
reimplementing it. Result at the sync commit below: **AUDIT: PASS, 0
violations** (I1: 283 stamps checked, 46 fresh PASS, all byte-backed; I2: 303
diffs regenerated byte-exact plus 2 named exceptions; I3: 287 of 287 mirror
hashes; I4: 287 of 287 rows both directions; I5: 96 of 96 ids exactly once;
I6: 303 of 303 candidates byte-equal). Machine record: `audit-results.txt`.
The audit was itself shown to fail: one scratch violation per invariant, in a
throwaway copy, is named by the corresponding check (recorded in the campaign
report formal/AUDIT.md, outside this repo).

Named exceptions, each with its ground in the code or the record: the
amethyst-v2 stamp special case (`build_review.AMETHYST_LINES`); the two
hand-authored diffs (`build_review.HAND_AUTHORED_DIFFS`:
license-box-theme-jp, whose record is a signed statement in place of a diff,
and peroxide-jp-base-css); the two site packages (scp-jp-storage,
scp-jp-sandbox3), whose stamps are status stamps from status.tsv and which
have no canonical page copy; the JP-original directory aliases (min-theme,
shushuin) and the /start alias rows (Sigma-10, Telecom, Amethyst).

## How to rerun

From the repository root:

    python3 formal/audit_repo.py
    cd formal
    for c in True StampNoCompare MirrorRecopy RegenSkip SyncSkip; do
      java -jar /path/to/tla2tools.jar -config SigmaReview$c.cfg SigmaReview.tla
    done

The true protocol must report "No error has been found"; each variant must
report its invariant violated. The audit must exit 0 (2 means its vendored
coverage ledger, `formal/coverage-ledger.md`, is missing; 1 means violations,
each named).

## Scope, stated honestly

The TLA+ model is a faithful abstraction, not a byte-level reimplementation:
two packages, content reduced to two values, `diff.md` reduced to a
truthfulness flag. It proves the protocol's guard structure cannot produce an
untruthful committed state through the modeled actions. The audit proves the
current tree is in a truthful state. Neither proves that a port is a *good*
port; that judgment is the review standard itself (the go-sign record and the
per-theme packages). I4 and I5 are proven at the byte layer only; their
protocol actions (index regeneration, ledger maintenance) are single
maintainer steps with no interleaving hazard the model would add information
about.

## Verification history

Verified against the tree at commit 8db9331 (the formal/ directory itself is
additive). At landing, the coordinator's independent re-run caught one defect
in this deliverable: the audit resolved its coverage ledger through a path
outside the repository, so outside the author's worktree it silently audited
against an empty ledger. The ledger is now vendored at
`formal/coverage-ledger.md`, a missing ledger is a hard error (exit 2), and
the failure modes were re-demonstrated after the fix. When the covered
machinery changes, rerun both layers and move this section's commit forward;
`formal/SKILL.md` is the standing instruction for that.
