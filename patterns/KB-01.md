# KB-01 — Unencoded colon in an asset URL path segment

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff, live-probe
- **Dedupe key:** asset URL / literal colon in a local--files path segment / staff checker unencoded-colon or token grep
- **Support:** 2 (static-diff, live-probe)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Wikidot file URLs embed the page fullname in the path
(`local--files/file:<id>/…`, `local--files/nav:side/…`). A raw colon in that
segment makes the reference malformed for the checker's link validation and
fragile in delivery; encoding only the path-segment colon to `%3A` preserves the
target exactly (same file serves, redirect-following HEAD 200).

## Static detection

In the candidate file `pages/theme:<slug>-jp.txt`, grep for `local--files/` and
`local--code/` URLs and for `file:[0-9]` / page-name segments containing a
literal `:` after the host. Equivalently run the staff checker and read code
`unencoded-colon`. Gate any fix on a redirect-following HEAD 200 for the encoded
form; if the encoded form does not serve, do not encode (5k precedent, AGENTS.md
section 3).

## Confirmed instances

blankstyle (3 lines), foxtrot (incl. the `nav:side` page-name segment case),
plus 5 further themes in the 15-error / 7-theme set: REPORT-GOSIGN2-FIX-MECH
(file evidence + HEAD 200 per theme); T1 class in REPORT-GOSIGN2-SOURCE section
5.

## False positives and disposition

`@@…@@` escaped documentation text is exempt; CSS `/*…*/` comments are NOT
exempt. Unflagged occurrences are left alone. Class (i): fix in candidate.

## Fix

Encode only the flagged path-segment colon(s) to `%3A`, nothing else in the URL.
