# KB-14 — Cross-theme / original-delivery code import (localize pattern 4)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** code delivery / candidate CSS imported from original-branch or third-party delivery / live @import and local--code host classification
- **Support:** 1 (static-diff)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

A candidate whose live CSS is @imported from the original branch's delivery (EN
CDN `cdn.scpwiki.com`, the original's GitHub Pages, a third-party host) is not
self-contained on JP: the JP wiki renders whatever the foreign host serves
today, the port's own edits never reach readers, and the delivery can change or
vanish independently of SCP-JP.

## Static detection

Extract every live `@import` and `local--code` URL from `[[module CSS]]` blocks
and the page's own code blocks; classify hosts. Original-site hosts, EN-CDN
theme paths, and third-party code hosts (other than the sanctioned JP artifacts
in AGENTS.md section 5: `scp-jp.github.io/Black-Highlighter`, the
`scp-jp.github.io/sigma` artifact, the draft-host form of a JP candidate) are
the defect. Only live code counts: `@@…@@` examples and prose are untouched.

## Confirmed instances

bedrock: entire theme CSS delivered live from `cdn.scpwiki.com` EN CDN plus the
rsms.me chain (LOCALIZE-A row 4). basalt: live theme CSS + interwiki args from
`jsdelivr.net/gh/Rokurolize/Basalt` third-party host (LOCALIZE-A row 3; the fork
delivery is the port's distribution form per AGENTS.md section 6, the finding is
the candidate importing the ORIGINAL-side delivery lines unchanged).
monotypical: normalize-only EN-CDN import, fixed by repointing to basalt-jp's /7
fragment (FIX-P4 U1/U2, FIX3-BF). broken-world: logo fragment imported from the
EN original, ported as `fragment:broken-world-jp` (FIX-P4 U3, FIX3-BW).

## False positives and disposition

A theme importing its OWN original as self-delivery is recorded, not edited;
imports of `scp-jp.github.io/Black-Highlighter/…` are the sanctioned JP form;
JP-production imports of themes that exist on real scp-jp (internal-affairs to
`theme:jakstyle/1`, shancheng to `theme:fossil/1`) are posting-correct.

## Fix

Repoint compiled-CSS delivery to the JP candidate's draft-host `local--code`
URL; repoint live includes by role equivalence (AGENTS.md section 5 procedure).

## Variant merged 2026-11-17: live-original remote-URL layering (A13-6)

Two candidates deliver their base by layering the LIVE original's
code by remote URL, unlike all siblings (which vendor the base, import
the JP base's code, or pull a JP distribution): animal-instead-of-beast-jp
(second interwiki-style include, lines 22-24, `theme=` URL is the
original's `local--code` on scpko.wikidot.com) and path-of-jinin-jp
(lines 22-24, original's `local--code` on scp-jp.wikidot.com). These
render with whatever the live original page currently serves, so an
upstream edit changes the candidate's rendering with no repo change.
Disposition: the contract (live-layering acceptable for posted-original
bases, or vendor like the siblings) is decided once and recorded; do
not charge per-theme until then. Source: findings/A13.md, A13-6.

## Amendment (2026-11-17, patterns-wave3 extraction): parameter gates, zero-delivery, deployment pairing, neutralization

Four refinements to the delivery-check family. (1) Deployment/candidate pairing: a finding made by fetching the draft host measures the DEPLOYMENT, not the candidate; before charging or dispositioning, run the same byte-level check over the canonical candidate's corresponding region and report the pair (BATCH-MPURE4 proposal 2; flopstyle-dark /2). (2) Parameter-gate inventory: before any delivery consolidation, inventory the original's `{$` gates and include-slot definitions; the port must re-implement each gate in the JP form or strike the teaching documentation (BATCH-MPURE9 proposal 1, BATCH-MPURE5 proposal 3, BATCH-U6 (c)). The gate/slot shapes are the subject of the new KB-73; this entry carries the delivery-import leg. (3) Zero-delivery form: the original delivers its base (hidden include or @import) and the candidate carries only override variables presupposing that base, with no delivery in any form — census the candidate for base delivery whenever the original carries one and the candidate sets base-namespaced variables (BATCH-RFIX20 proposal 2, winddew-in-hand W1). (4) Neutralization form: a personal-domain delivery that fed both a module import and a frame, where the candidate replaces `theme=` with a prose placeholder, preserves `css=`, and resolves priority in a later wave — record as the neutralization form so sweeps do not re-charge the placeholder as a broken URL (BATCH-RFIX12 proposal 3, share-future). (5) Dependent-theme delivery: import from the base's JP candidate exactly what the original imported from the base, no more (BATCH-MPURE7 proposal 4; laruetheme, lumina, monotypical).
