# KB-50 — `hidden-rate` machine line false shapes

- **Class:** E. Capture and measurement artefact, not a result
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

render_check flags `hidden-rate` when it cannot find a visible rating widget.
Two shapes are not defects: (a) the source has no `[[module Rate]]` and no
rate-bearing credit module, so there is correctly nothing to find (correct
machine behaviour, per AGENTS.md section 3); (b) the widget IS visible and the
script's probe fails (a script false positive).

## Static detection

For shape (a): grep the candidate/page source for `[[module Rate]]` and
`credit:start-preview`; absence of both settles it statically. For shape (b):
the T3 screenshot showing the rate widget settles it. Either check precedes any
charge.

## Confirmed instances

starbasalt: hidden-rate on all combos of both pages, T3-confirmed script false
positive (rate widget visible): RENDER-ROWS-G. halloween page hidden-rate where
the rating module is absent: RENDER-B row 14 (recorded with the source state).

## False positives and disposition

A candidate that SHOULD carry rate furniture and lost it is KB-09/KB-10
(source-side), not this pattern; this pattern governs the render line only.

## Fix

None.
