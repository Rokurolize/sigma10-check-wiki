# KB-27 — Mobile sidebar toggle missing in BOTH engines

- **Class:** B. Theme defect, triage only
- **Detection cost:** needs live probe
- **Provability:** TRIAGE
- **Status:** adopted
- **Basis:** measured-render
- **Dedupe key:** sidebar toggle / no reachable toggle in either engine at mobile widths / mobile-context hiding-rule recipe, render confirms
- **Support:** 1 (measured-render)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Distinct from the WebKit pair: at 375/320 no sidebar-open control is reachable
in either engine (machine `sidebar-unreachable` on mobile combos of both
engines, T3 confirms no toggle). The theme's mobile layout drops or buries the
toggle entirely, usually because its sidebar is a desktop-only construction and
the base's mobile toggle is suppressed by the theme's rules.

## Static detection

Triage: candidate suppresses or restyles the base toggle (`display: none` on
menu controls at mobile breakpoints, sidebar rules with no mobile variant), or
the theme predates the mobile toggle pattern. Compare the candidate's mobile
media queries against its base theme's.

## Confirmed instances

sound (page and sample, both engines; T3: missing mobile sidebar toggle
confirmed): RENDER-ROWS-G (CN14). starry page and suprematism (both engines at
375/320): RENDER-ROWS-G (CN15). yore (both pages): RENDER-ROWS-G (CN18).

## False positives and disposition

Do not merge with KB-25/26: the both-engines shape has a different mechanism and
fix. A toggle that exists but is overlapped by preview chrome at one width is
KB-34 territory; T3 must confirm no toggle is reachable.

## Fix

Restore a reachable mobile toggle following the base theme's pattern.
