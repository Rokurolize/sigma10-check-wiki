# KB-48 — Blank body from test-wiki page tag state (iftags gate vs page tags)

- **Class:** E. Capture and measurement artefact, not a result
- **Detection cost:** needs live probe
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Theme bodies are gated by `[[iftags +テーマ]]`. A test-wiki page carrying the tag
`theme` instead of `テーマ` never satisfies the gate, so its body renders blank no
matter what the candidate's CSS says. The defect is the wiki page's tag state,
not the candidate. Basalt's original delivery has the same anatomy (all six code
blocks inside the gate), which is why the shape recurs.

## Static detection

Before dispositioning any blank body: read the test-wiki page's tags (page HTML
or API) and check for `theme` vs `テーマ`. Tag mismatch proven from the page HTML
settles it. ALSO check cache state (KB-49) before final disposition, per the
open caution in AGENTS.md section 9.

## Confirmed instances

al-slop, basalt, scpedia blank bodies proven as tag mismatch from page HTML:
REPORT-GOSIGN2-RENDER-A; recorded in AGENTS.md section 3 blank-body caution.

## False positives and disposition

inkblot's blank body was recorded as possible stale cache, NOT counted as this
pattern (RENDER-B row 16); the two mechanisms must not be merged without the tag
evidence.

## Fix

Correct the test-wiki page's tags (page state), never the candidate.
