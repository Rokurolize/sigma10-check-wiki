# KB-18 — Untranslated visible text, including CSS `content:` strings (pattern 10 / T5)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** cross-file diff
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Reader-visible strings survive translation in three hiding places: body/usage
text left in the original language, sample/exhibit text, and CSS `content:`
strings (labels, badges, pseudo-element text) that no wikitext scan sees. After
migration these render as foreign-language UI on the JP wiki.

## Static detection

Grep the candidate for `content:` declarations and read every string value; scan
body and usage sections for untranslated prose (headings, button labels, sample
text). Judge against the original: in-universe proper nouns are intentional
residue (see false positives).

## Confirmed instances

ad-abyssum-penumbra: untranslated Hebrew CSS strings (RENDER-S2-A summary,
section 5/T5). cosmonaut: untranslated "by Some Dude" in the reader-visible fake
footer sample (LOCALIZE-A row 7). aesthetic: stale reader-visible font name in
usage text (T5 finding 1).

## False positives and disposition

EN in-universe proper nouns (UIU/FBI, SPC DATABASE, GoI names) are intentional,
not findings. Plain 翻訳責任者 wording and 元記事リンク link text other than the 原題 are a
once-per-report uniform nit, not per-row failures (AGENTS.md section 3 T5).

## Fix

Translate the string in the candidate (CSS `content:` included), keeping
in-universe nouns.
