# KB-24 — Narrow-width header clipping / collision

- **Class:** B. Theme defect, triage only
- **Detection cost:** needs live probe
- **Provability:** TRIAGE
- **Status:** adopted
- **Basis:** measured-render
- **Dedupe key:** header layout / narrow-width header clipping or collision (wordmark size, wordmark replacement, frame collision, toggle-login overlap) / sub-mechanism signals, render confirms
- **Support:** 1 (measured-render)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

The theme's header (wordmark, logo, account/menu row) is laid out at desktop
widths with fixed-size elements. At 375/320 the Sigma-10 header contract shrinks
the bar but the theme's elements do not, so the wordmark clips at the right
edge, the gold frame collides with the test-wiki header, or the menu toggle
overlaps the sign-in block and intercepts its clicks.

## Static detection

Look for fixed pixel widths/heights on header selectors (`#header`, `.header`,
wordmark/logo rules), large fixed font sizes for the wordmark, and absolutely
positioned header elements without a ≤375 media query. Family resemblance helps:
themes derived from a common base (the 3law family) inherit the signature
together.

## Confirmed instances

3law-pride, 3lawcracked, alcur-theme, alexylva-university, ambrose-chapter-two,
art-deco, aces-and-eights (wordmark clips at 320): RENDER-S2-A summary cluster
(a). foxtrot: 320px toggle/sign-in overlap with the `.open-menu a` click
deterministically intercepted by `login-status`: REPORT-GOSIGN2-RENDER-B row 13.
art-deco: frame collides with the default header (RENDER-S2-A).

## False positives and disposition

Preview-notice clipping at the same widths is KB-34, not this pattern; check
whether the clipped element is theme header or wiki chrome.

## Fix

Add the narrow-width header rules (scale/clip the wordmark, stack the account
row) in the candidate, per family where inherited.
