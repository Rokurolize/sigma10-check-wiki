# KB-31 — Credit-modal overflow on real-module pages

- **Class:** B. Theme defect, triage only
- **Detection cost:** needs live probe
- **Provability:** TRIAGE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Distinct from the preview-form artefact (KB-32): on pages using the REAL credit
module, a theme whose modal or credit block is wider than a ≤375/320 viewport
makes the modal itself overflow the screen. This is candidate-inherent
(AGENTS.md section 3 T2 states it explicitly) because the real module's
behaviour is the theme's responsibility.

## Static detection

Triage: fixed widths above 320 on modal/credit selectors (`.modalbox`, credit
block containers) in a candidate whose pages use the real credit module (not
`credit:start-preview`). The preview-form check comes first: if the page uses
the preview module, KB-32 applies and this pattern cannot be charged from that
page.

## Confirmed instances

cosmos: credit-modal-overflow at 320 (RENDER-S2-A summary cluster (e)).

## False positives and disposition

Any `credit-modal` error on a preview-module page is KB-32, never this pattern.
The static replica's overflow is KB-33.

## Fix

Constrain the modal/credit block to the viewport at narrow widths in the
candidate.
