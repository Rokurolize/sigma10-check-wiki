# KB-04 — Malformed Google Fonts @import (hyphens where `+` is required)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** cross-file diff
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Google Fonts family names with spaces must be encoded with `+` in the css2/css
API URL (`family=Poiret+One`). A port that writes the family with hyphens
(`family=poiret-one:400`) gets HTTP 400; the font never loads and every element
in that stack falls back, on both engines, while the CSS itself looks plausible.

## Static detection

Grep the candidate for `fonts.googleapis.com` URLs; for each `family=` value,
check that multi-word families use `+`, not `-`, between words (weight/style
suffixes after `:` are fine). Compare against the original's own font URL at the
reference revision.

## Confirmed instances

art-deco: three malformed imports (`poiret-one`, `andada-pro`, `roboto-flex`,
canonical lines 28-30), HTTP 400 / ORB block, fonts never load:
REPORT-GOSIGN2-RENDER-S2-A.

## False positives and disposition

Single-word families are unaffected. `fonts.bunny.net` URLs follow a different
grammar (see KB-17). Class: candidate-inherent dead declaration (AGENTS.md
section 3 T2).

## Fix

Rewrite the family parameter with `+` exactly as the original's serving URL
does.
