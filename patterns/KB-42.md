# KB-42 — http-scheme URLs (posting scheme rewrite)

- **Class:** D. Environment-layer
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Candidates carry `http://` URLs inherited from originals. The right host and
file serve over both schemes today, so nothing breaks at draft stage; the scheme
is rewritten to https at posting by procedure.

## Static detection

Grep the candidate for `http://` in live references. Class (ii) on sight, per
the settled tie-break exception in AGENTS.md section 3 (http never goes to class
(i)).

## Confirmed instances

foxtrot: 30 `http` errors of its 33 in T1-BASELINE, all class (ii).
Campaign-wide in SOURCE/SOURCE2 classifications.

## False positives and disposition

An http URL whose host is dead is KB-02, not this pattern; an http URL inside an
include parameter with a stray space is KB-21.

## Fix

None in the candidate; do not edit (AGENTS.md section 3: do not edit).

## Instance merged 2026-11-17: http-scheme CSS asset (A13-7)

admo-jp loads a logo over plain http from a test wiki inside its CSS:
`--logo: url('http://scptestwiki.wikidot.com/local--files/sigma%3Abasalt/basalt_scp_logo-for_lightmode.svg')`
(pages/theme:admo-jp.txt line 459). It is the only http:// URL among
the 13 candidate files containing one that is a CSS asset rather than
a prose or license link (the other 12 are prose: user:info links,
scp-jp page references, license URLs, and are not charged). On an
https page this is a mixed-content risk, and the host is a test wiki,
not SCP-JP storage or a permitted CDN. Fix: point --logo at the https
SCP-JP-storage (or check-wiki) copy of the same Basalt logo asset,
matching how basalt-jp references its assets. Source:
findings/A13.md, A13-7.
