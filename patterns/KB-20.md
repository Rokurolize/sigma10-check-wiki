# KB-20 — Oversize candidate from inlined base material

- **Class:** A. Theme defect, file-provable
- **Detection cost:** cross-file diff
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Wikidot refuses page sources over 200,000 characters, and the refusal surfaces
as a generic save error easily misread as a lock or captcha failure. Candidates
that inline base material (a framework's or shared base theme's full CSS)
instead of mirroring the original's file separation cross the limit and cannot
be saved or posted at all.

## Static detection

Character-count every candidate file; flag anything approaching 200,000. For
flagged files, check whether base/framework CSS is inlined that the original
delivers from its own include-target page or external @import; the candidate
should carry only its own CSS.

## Confirmed instances

betwixt, kitchen, peroxide, magazine all exceeded the limit this way and had to
be restructured (AGENTS.md section 7 oversize rule; LOCALIZE-S2 records).
Peroxide's base now lives in `fragment:peroxide-jp-base-css` / `-elements-css`;
parallel's in `theme:parallel-jp`.

## False positives and disposition

A large candidate whose size is its own CSS (not inlined base) is not this
pattern; the mechanism is the inlining, not the size alone.

## Fix

Move the base material to its own include-target page or external delivery,
mirroring the original's separation.
