# KB-76 — Duplicated short block at the file tail

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** duplicated tail block / the same short [[div]] block appearing twice adjacently at a file tail where the original carries it once / exact-duplicate short-block census with candidate count greater than original count
- **Support:** 1 (static-diff)
- **Evidence source:** R/review-scout/BATCH-RDISP10.md proposal (rima residue B89).

## Mechanism

A copy/paste slip leaves the same short `[[div]]` block twice at the tail
of a candidate where the original carries it once. The duplication reads
as residue (no signature claims it) and renders the block twice. It is a
different mechanism from KB-65 (a duplicated @import line, cached and
visually harmless) and from KB-59's escaped exhibits.

## Static detection

Census short `[[div]]`/`[[div]]`-close blocks at each file tail; flag an
exact-duplicate pair whose candidate count exceeds the original's count
at the corresponding tail. Restrict to short blocks and adjacency so
long documentation exhibits are not swept in.

## Confirmed instances

rima (residue B89, the same short div twice at the file tail where the
original carries it once). One instance in the source batch; the recipe
is the instrument for completing the set.

## False positives and disposition

A paired specimen with two similar but non-identical blocks is not a hit.
A deliberate repeated exhibit with a recorded ground is dispositioned,
not charged. A duplicated @import is KB-65.

## Fix

Delete the duplicate copy, leaving one, after confirming the original's
count at that tail.
