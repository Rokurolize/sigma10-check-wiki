# KB-08 — iftags gate anomaly (bare `[[iftags]]` with no condition)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Theme CSS and furniture are normally gated by `[[iftags +テーマ]]` so they apply
only on theme-tagged pages. A bare `[[iftags]]` with no condition is
nonstandard: Wikidot's empty-spec handling applies it unpredictably, so an
include wrapped in it (e.g. the BHL base include) loads under rules no other
theme follows.

## Static detection

Grep the candidate for `\[\[iftags\]\]` with no tag argument on the same line,
and for gates naming tags other than the campaign's `+テーマ` form.

## Confirmed instances

aesthetic-theme lines 1-3 wrap the BHL page include in a condition-less
`[[iftags]]`: REPORT-GOSIGN2-LOCALIZE-A row 1 (pattern 2 note).

## False positives and disposition

Properly conditioned gates (`+テーマ`, `+theme` on original-delivery pages) are the
norm, not findings. Related but distinct: the wiki page's own tag state breaking
the gate at render is KB-48.

## Fix

Give the gate the standard `+テーマ` condition or remove the wrapper to match the
original's structure.
