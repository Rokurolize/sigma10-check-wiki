# KB-47 — Single-combo ORB / load-failed flakiness (asset-host artefact)

- **Class:** E. Capture and measurement artefact, not a result
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Wikidot's file hosts intermittently ORB-block or fail a single asset at a single
engine/viewport combo while serving it everywhere else (cache and edge
variance). The machine records a `load-failed` that looks identical to KB-05's
MIME defect but does not reproduce.

## Static detection

Count the combos: a `load-failed` / ORB line on exactly ONE engine-viewport
combo, with the same asset loading at all other combos (and the element visibly
rendered in other captures), is flakiness. Consistency across combos is what
promotes it to KB-05.

## Confirmed instances

font-bauhaus.css single-combo ORB lines in RENDER-S2 reports ("single-combo
ORB/asset-host artifact, X7 family"). jfdot-mp12.css ORB-blocked at chromium 768
only, pixel face rendering at every other width/engine: RENDER-S2 reports
("candidate-inherent flakiness of the storage-hosted font, not a hard failure").

## False positives and disposition

Do not use this pattern to clear a consistent failure; the combo count is the
evidence.

## Fix

None; note to the author only if it reproduces.
