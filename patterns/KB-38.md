# KB-38 — `sidebar-position` warn against the Sigma-9 baseline

- **Class:** C. Cross-cutting, not a defect
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** measured-render
- **Dedupe key:** sidebar-position warn / machine warn measured against the Sigma-9 baseline while the JP position is correct / report-text signature, T3 position check
- **Support:** 1 (measured-render)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

render_check compares the sidebar's x position against a baseline captured from
the Sigma-9-era layout. JP Sigma-10 themes place the sidebar at the left JP
position, which differs from that baseline, so the machine warns on correctly
placed sidebars (including BHL flush-left x=0 layouts).

## Static detection

Disposition: a `sidebar-position` warn is never charged on its own. The JP
position is verified visually once per theme (sidebar at left, opens on mobile);
if the screenshot shows the JP position, the warn is this artefact.

## Confirmed instances

shark-punching-centre-bhl page (warn at 1366, T3 confirms left JP position and
mobile open): RERUN16. BHL-derivative themes' x=0 warns are the flush-left
layout, eyeball-confirmed present at far left: RENDER-S2 reports.

## False positives and disposition

A sidebar that is actually missing or unreachable is KB-25/26/27; the warn alone
neither proves nor clears those.

None.
