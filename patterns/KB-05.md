# KB-05 — Asset served with a non-CSS MIME type (one defect, two engine faces)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** needs live probe
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Wikidot file storage can serve a stylesheet or font with `Content-Type:
text/plain`. Chromium blocks it via ORB; WebKit rejects it as a non-CSS MIME.
The same file therefore appears as an ORB `load-failed` in Chromium and a
404/reject in WebKit; lanes repeatedly nearly counted it as two defects. The
theme's typography silently falls back wherever the asset is the only source.

## Static detection

For every candidate-own stylesheet/font URL (in `@import`, `<link>`-equivalent
includes, `local--code` deliveries), issue a HEAD request and record
`Content-Type`; flag anything loaded as CSS whose type is `text/plain` (or
missing). Distinguish from KB-47 by checking ALL viewports' summaries: a MIME
defect fails consistently, flakiness fails once.

## Confirmed instances

inkblot: WebKit CSS non-CSS-MIME reject: REPORT-GOSIGN2-RENDER-B row 16. y2k
`logo.png` ORB-blocked in Chromium at ≤768 (its reference form is separately
KB-21): REPORT-GOSIGN2-RENDER-S2 reports. art-deco draft stylesheet ORB (asset
artefact noted alongside KB-04): RENDER-S2-A.

## False positives and disposition

A single-combo ORB line with the asset rendering at every other width/engine is
KB-47 flakiness, not this pattern. Charge once, as one defect.

## Fix

Re-host or re-deliver the asset so it serves with a CSS/image MIME, or add a
fallback stack; the reference form must not rely on the mis-served copy.
