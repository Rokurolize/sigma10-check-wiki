# KB-41 — Draft-host references (pseudo-ref / draft-host info)

- **Class:** D. Environment-layer
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff, lane-report
- **Dedupe key:** draft-host reference / sigma10-jp-test.wdfiles.com local--code delivery in candidate text / draft-host grep census
- **Support:** 2 (static-diff, lane-report)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Candidates are staged on the draft host (`sigma10-jp-test.wdfiles.com`), so
their own code deliveries and file references point at that host by
construction. The checker reports them as `pseudo-ref` errors / `draft-host`
info; at posting they are rewritten to `scp-jp.wdfiles.com` /
`scp-jp-storage.wdfiles.com` by procedure. A repoint to the draft host
deliberately CREATES a pseudo-ref; that is the correct draft-stage end state.

## Static detection

Any checker `pseudo-ref` whose target host is the draft host, and any
`draft-host` info line, is sanctioned draft form: class (iii) for the
candidate's own `local--code`, class (ii) for its own attachments and cross-page
draft references. Do not edit the candidate to clear them.

## Confirmed instances

T1-BASELINE: pseudo-ref is the dominant error code across the 287 (e.g. basalt
23 of 33 errors); AGENTS.md sections 3 and 5.

## False positives and disposition

A pseudo-ref-shaped reference to a host that is NOT the draft host is not this
pattern; read the host.

## Fix

None in the candidate; posting procedure rewrites.
