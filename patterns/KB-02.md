# KB-02 — Genuinely dead asset reference

- **Class:** A. Theme defect, file-provable
- **Detection cost:** needs live probe
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

The candidate references an asset (image, CSS background, code file) at a URL
that no longer serves anywhere: the original author moved or deleted it, or the
URL was a placeholder from the start. At render the element is simply absent
(flat header, missing logo), indistinguishable in a screenshot from the
deferred-asset state (KB-58) unless the URL itself is probed.

## Static detection

Extract every external URL from the candidate (do NOT truncate at parentheses;
truncated extraction manufactured false dead references). For each suspect: (1)
compare against the branch original at its current revision; (2) hunt the
asset's real home in the original's own file list / author's wiki / hosting
named in the original source; (3) probe HEAD, then GET, then descriptive-UA GET;
serving under any pass means serving. Repoint only on sameness evidence (exact
filename + identical usage, or the original's own file list containing it).

## Confirmed instances

bloodraven `fondo-code.png` (repointed to the author's current hosting, HEAD
200) and eigenmachine `understill.gif` (repointed to the original's own
storage): REPORT-GOSIGN2-FIX2-DEADREF. 8 ORIGINAL-DEFECT lines in the same
report left byte-unchanged.

## False positives and disposition

suprematism and trauma `White_on_White` serve 200 at the complete untruncated
URL (parenthesis truncation artefact, see KB-51). Archive snapshots are not a
home; a different-colour variant is not the same asset. No serving source: leave
byte-unchanged, record ORIGINAL-DEFECT.

## Fix

Repoint to the evidenced real home only.
