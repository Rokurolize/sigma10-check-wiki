# KB-80 — footnoteblock added where the original used inline footnotes

- **Class:** C. Cross-cutting, not a defect
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** footnoteblock addition / a candidate adding [[footnoteblock]] where the original's exhibit uses inline [[footnote]] / original-candidate footnote-element census
- **Support:** 1 (static-diff)
- **Evidence source:** R/review-scout/BATCH-RFIX3.md proposal P2 (deepspace B44).

## Mechanism

A candidate adds a live `[[footnoteblock]]` at a tail where the original
used inline `[[footnote]]` elements without a block. This is a rendering
supplement the port introduced to make footnotes visible on JP, not a
defect: the classifier currently leaves the block as residue, so each
package re-derives that the addition is benign. It is the mirror of the
escaped/dropped-block family (KB-59): there the block is suppressed, here
it is added.

## Static detection

Census `[[footnote]]` and `[[footnoteblock]]` elements on both sides.
Flag a candidate whose original carried inline footnotes and no block
while the candidate carries a live block. Confirm the block's position
and that footnotes exist to be collected.

## Confirmed instances

deepspace (candidate B44 adds a footnoteblock where the original exhibit
used inline footnotes).

## False positives and disposition

An escaped `@@[[footnoteblock]]@@` exhibit is KB-59, not this pattern. A
dropped block where the original carried a live one and footnotes remain
is a different shape (also KB-59's family). A footnoteblock that renders
no footnotes at all is a defect, not this class.

## Fix

No candidate edit. Record the addition in the explanation's Structure
section as a rendering supplement, so a reviewer reads it as intentional
rather than residue.
