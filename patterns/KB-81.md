# KB-81 — Wikilink converted to a third-party absolute URL that does not resolve

- **Class:** A. Theme defect, file-provable
- **Detection cost:** needs live probe
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** live-probe, static-diff
- **Dedupe key:** link conversion / a bare [[wikilink]] converted to an absolute URL on a host that is neither the origin wiki nor the JP wiki, changing the link's resolution / two-form HEAD probe plus host classification
- **Support:** 1 (live-probe, static-diff)
- **Evidence source:** R/review-scout/BATCH-RFIX6.md proposal 2 (LINK-REPOINT flag 2).

## Mechanism

A port converts a bare wikilink into an absolute URL on a third-party
host. The conversion changes how the link resolves, not just its
spelling: the original's bare form resolves to a live page while the
converted absolute form can 404. A generic LINK-REPOINT label that calls
the block clean hides the break.

## Static detection

Find blocks where a candidate absolute URL corresponds to an original
bare wikilink. Classify the target host: if it is neither the original's
host nor the candidate's wiki, probe BOTH forms with HEAD (following
redirects) and compare. A 404 on the converted form with a 200 on the
original's resolution is the hit, whatever class disposition covers the
theme's links generally.

## Confirmed instances

The R-fix-6 flag-2 conversion instance (absolute URL on a third-party
host; original bare form resolves, converted form does not).

## False positives and disposition

A conversion to the origin wiki's or the JP wiki's own host is a normal
repoint, not this pattern. A link whose converted form serves is a clean
repoint. A dead asset URL is KB-02; a dead prose link to a page name is
KB-66.

## Fix

Keep the original's bare form (or repoint to the verified JP page) so the
link resolves at posting. Do not leave a third-party absolute form that
fails the probe.
