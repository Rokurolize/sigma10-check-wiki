# KB-21 — Fragile asset reference form (stray space and http scheme inside an include parameter)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** include parameter / stray space plus http scheme inside an image-block parameter / parameter-form grep
- **Support:** 1 (static-diff)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

An `[[include component:image-block name= http://…]]` with a leading space
inside the parameter value and an `http://` scheme produces a malformed asset
URL after Wikidot's rewriting; Chromium ORB-blocks the response at some
viewports while others load from cache, so the same logo appears and vanishes
across widths.

## Static detection

Grep include parameters for `= ` (equals followed by a space before the value)
and for `http://` asset URLs inside include parameters and `[[image]]` sources.

## Confirmed instances

y2k `logo.png` (candidate line 44): broken-image icon at 768/375/320 in
Chromium, loads at 1366 and in WebKit: REPORT-GOSIGN2-RENDER-S2 reports.

## False positives and disposition

`http` URLs generally are class (ii) posting rewrites (KB-42); this pattern is
the parameter-form fragility (space + scheme inside the include), which is
candidate-inherent as authored.

## Fix

Drop the leading space, use `https://`, verify the file's ORB posture.
