# KB-65 — Duplicated @import lines

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** CSS @import / the same @import URL duplicated anywhere in one candidate file / file-level duplicate-URL scan, both channels
- **Support:** 1 (static-diff)
- **Evidence source:** sigma10-review-20261117 findings/A13.md, finding A13-10 (full-population duplicate-@import scan).

## Mechanism

A supplement block pasted twice leaves the identical `@import` line
repeated in a candidate's CSS. At render the second fetch is cached,
so the duplication is harmless visually, but it doubles the lines a
maintainer must keep in sync and is a reliable marker that the block
was pasted without review.

## Static detection

RECIPE RESTATED FILE-LEVEL (coordinator ruling, SWEEP-D,
2026-11-17): within each candidate file, extract all `@import` lines
(both CSS channels) and flag any exact duplicate URL appearing more
than once ANYWHERE in the file. A duplicated @import of one URL is
the same mechanism whether the copies sit in the same block or across
blocks; A13 itself counted the cross-block files borealis and
frownstyle. Severity: hygiene.

## False positives and disposition

Two @imports of different URLs from the same host are not duplicates.
A repeated @import in different gated blocks (e.g. inside separate
iftags branches that cannot co-fire) is noted with its gating; under
the file-level recipe restated above it still counts in the hit set,
with the gating recorded. normal-jp's Parallel preset duplicates
across parameter-gated module CSS blocks are the gated shape and are
noted only; its same-block parallel-jp/1 consecutive pair stands as a
hit.

## Fix

Deduplicate during the next touch of each file; no standalone sweep
is needed (A13-10 proposed fix).
