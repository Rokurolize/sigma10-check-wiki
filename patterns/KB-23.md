# KB-23 — Candidate fixed min-width page-overflow

- **Class:** B. Theme defect, triage only
- **Detection cost:** needs live probe
- **Provability:** TRIAGE
- **Status:** adopted
- **Basis:** measured-render
- **Dedupe key:** page layout / fixed min-width, own, base-carried, or family-carried, overflows the candidate page at phone widths / family-first recipe, render confirms
- **Support:** 1 (measured-render)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

The candidate's own CSS sets a fixed minimum content width (a `min-width`, a
fixed-width layout grid, a 512px-and-up component) wider than phone viewports.
Sigma-10's fluid base cannot shrink it, so the candidate page itself overflows
horizontally at 375/320 (and the theme is unusable on mobile after migration).

## Static detection

Grep the candidate CSS for `min-width` and fixed `width:` values above 320px on
layout-level selectors (body, #content-wrap, main containers, the theme's
signature components). Values above 375 on a candidate-page (not sample)
selector are a strong signal; values in the 337-419 band on SAMPLES are KB-33
until attributed.

## Confirmed instances

The fixed min-width family on candidate pages: 512-onwards, 5k, admo,
alcur-theme, black-diamond, blood, ch-scp-theme, chaos, cosmos (RENDER-S2-A
summary cluster (b)); ordopharm page overflow 506-518px at 320/375 both engines
(RERUN16); kitchen fixed widths 1024/1025 predicted statically and confirmed as
theme-own surface (RERUN16-PARTIAL + RERUN16).

## False positives and disposition

Sample-page overflow in the cross-cutting shapes is KB-33. Deliberate
fixed-width specimens inside sample content are KB-37. The charge is
candidate-PAGE overflow from the theme's own rules.

## Fix

Make the offending component fluid below its fixed width (max-width +
width:100%, or a mobile breakpoint), preserving the desktop design.
