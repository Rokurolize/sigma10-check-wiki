# KB-06 — Unsubstituted include variable rendered literally

- **Class:** A. Theme defect, file-provable
- **Detection cost:** cross-file diff
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Wikidot include variables (`{$name}`) are substituted only when the including
page passes the argument. A candidate (or its included fragment) that references
a variable nobody passes renders the literal text `{$sous-titre}` /
`{$priority}` to readers, in the header or in console errors, on every page
using that include.

## Static detection

Grep the candidate and its campaign fragments for `\{\$[a-z-]+\}`. For each hit,
check the corresponding `[[include …]]` call sites pass that argument
(`name=value`). A variable with no supplying call site is the defect. Also grep
checker/console outputs for the same literal.

## Confirmed instances

quand-le-soleil-se-couche: header subtitle renders literally as `{$sous-titre}`
under the wordmark in every screenshot of both pages: REPORT-GOSIGN2-RENDER-S2
reports (D2 family). skipos: first interwiki-style include omits `priority`,
passing the unsubstituted default through (`Interwiki: rejected style with
priority{$priority}` console info): RENDER-S2 reports (see also KB-07).

## False positives and disposition

Variables inside `@@…@@` examples and variables supplied by a different call
site of the same fragment are fine; check every call site before charging.

## Fix

Pass the argument at the include, give the fragment a sane default, or remove
the redundant include (skipos form).
