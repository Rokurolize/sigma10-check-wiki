# KB-73 — Parameter-gated delivery dropped or emptied in the candidate

- **Class:** A. Theme defect, file-provable
- **Detection cost:** cross-file diff
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** parameter gate / an original {$param}-gated delivery module or include slot that is absent, emptied, or undocumented in the candidate / both-sides gate census plus slot-module and import-body check
- **Support:** 3 (static-diff)
- **Evidence source:** R/review-scout/BATCH-MPURE9.md proposal 1, BATCH-MPURE13.md proposals 1-2, BATCH-MPURE5.md proposal 3, BATCH-U6.md proposal (c), BATCH-RFIX15.md proposal (c).

## Mechanism

Originals gate features on include parameters: a `{$param}`-gated
`[[module CSS]]` block, a `[!-- {$param} --]` conditional-comment slot,
or a documented parameter that controls a preset. A port can drop the
gated module, leave the slot marker with no module, empty a gate pair of
its @import and rules, or teach parameters in documentation that no gate
in the file defines. Documentation for an installed parameter then
teaches a feature that cannot fire.

## Static detection

Inventory the original's parameter gates (`{$` occurrences in delivery
zones), enumerate include-slot definitions (`[!-- {$param}`) on both
sides, and check each gate pair's body. Flag (a) an original gate with no
candidate counterpart, (b) a candidate slot marker with no module, (c) a
gate pair whose body is empty or whitespace-only where the original's
wrapped content, and (d) a documented parameter with zero gate
definitions in the file. A delivery consolidation must either re-
implement each gate in the JP form or strike the teaching documentation.

## Confirmed instances

steam-guide (17 documented gates with zero definitions), parallel
(candidate gate pair L498-518 wrapped no @import or rules), foundom
(slot definitions 4 to 0; slot deletion), greystyle (include-parameter
module loss that passed every lane), our-open-veins and past-oriented
(parameter-gated features).

## False positives and disposition

A conditional-comment module or parameter-gated channel that serves a
different delivery path is NOT a KB-65 duplicate even when it shares an
@import: exempt it from KB-65's file-level duplicate tier and record it
here (xmas instance, NL entry drafted in this wave). Mutually exclusive
preset gates that cannot co-fire are not collisions (KB-07 amendment).

## Fix

Re-implement each original gate in the JP delivery form or remove the
documentation that teaches the parameter. Keep slot definitions paired
with their module. Where a gate is intentionally dropped, record the
disposition in the explanation rather than leaving an empty marker.
