# KB-16 — JP font load gap (localize pattern 7)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** cross-file diff
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** font stack / JP family named but not loaded, or a Latin-only stack overrides the JP base / stack-vs-load diff against base and original
- **Support:** 1 (static-diff)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

Sigma-10's JP base supplies JP font stacks (BIZ UDPGothic, M Plus 1p, Noto Sans
JP, Yu Mincho). A candidate breaks JP glyph rendering three ways: (a) a JP font
is NAMED in a stack but never loaded anywhere; (b) a Latin-only stack overrides
the JP base stack, so body/title JP glyphs fall back to OS defaults; (c) a JP
font is imported but never used. A dropped load (the original loaded the family,
the port lost the @import) is the same shape as (a).

## Static detection

Extract all `font-family` stacks from the candidate's CSS variables and rules;
extract all font loads (@import URLs, font hosts). For each stack: is every
named JP family either loaded or supplied by the JP base? Does the stack
override a base stack without re-adding a JP fallback? Is any loaded JP family
unused? Compare with the original at the reference revision to catch dropped
loads.

## Confirmed instances

aesthetic: `--body-font`/`--title-font` Latin-only stacks override the JP BHL
base, no JP font for body/title (LOCALIZE-A row 1). foxtrot: `--ui-font` named
IBM Plex Sans with no @import anywhere; the dropped load was restored from the
archived EN import by FIX3-B. al-slop: Noto Sans JP named but never loaded
(LOCALIZE-A row 2). Partial gaps are explicitly acceptable for classic,
cosmonaut, bedrock-mono, isolated-terminal, hansarp, jakstyle (AGENTS.md section
5).

## False positives and disposition

Header-only JP coverage is a partial gap, recorded as such, not automatically
display-affecting for every element; judge per stack (body/title stacks matter
most).

## Fix

Add the load plus JP fallbacks in the named stacks.

## Instance set merged 2026-11-17: font-family override without Noto Sans JP (A13-4)

Eleven candidates declare `font-family` in their own CSS (overriding
the site theme's stack, which is where Japanese glyphs would otherwise
come from) but contain no Noto Sans JP in either the `@import` URL
form or the `font-family` form: min-theme, scp-human-resources, blood,
crayon, decom-dept, dia-de-muertos, eigenmachine, fish,
internal-affairs, linear-black, magpie-swoops (all -jp candidates).
Base-inheritance caveat: magpie-swoops (SCP-JP BHL distribution base),
decom-dept and internal-affairs (BHL-based) must have their bases
checked before concluding the supplement is missing at render; the
other 8 are standalone or Sigma-based with no such base. min-theme is
also a named exception (JP original, Latin-only stack by construction;
verify rather than assume broken, findings/A13.md A13-8). Fix shape:
verify at render (Japanese text in the decoration sample), then add
the standard Noto Sans JP @import and font-stack fallback to those
that actually fall back to a browser default, matching their base
family's form. Source: findings/A13.md, A13-4. This is a named
instance set of this pattern (the JP font load gap), not a new
pattern.

## Amendment (2026-11-17, patterns-wave3 extraction): inversion, stack signatures, severity, include-chain duplication, delivered-channel check

The largest proposal family refines this pattern's stack-vs-load census. Adopt as named extensions (all repo-provable): (1) Load/use inversion — compare the original's and candidate's `@font-face` family sets against the candidate's `font-family` first-names and `@import` family parameters; report stacks-minus-loads and loads-minus-stacks (BATCH-RFIX1 proposal 1, 07k; BATCH-RFIX12 proposal 2, shancheng). The mirror shape — an @import load whose family no stack names — is one incoherence shape with stack-without-load (BATCH-RFIX2 proposal 3, BATCH-MPURE12 proposal 2, BATCH-U3 (b), BATCH-RFIX6 proposal 1). (2) Declared-substitution census — when a porter comment declares X replaced by Y, check the declaration against stacks and loads; plugsoft declares Gmarket→Gothic A1 while stacks still name Gmarket and Y is loaded but unused (BATCH-RFIX9 proposal 1). (3) Dead-face name — where a documented @font-face removal is made, stacks still leading with the removed face's known-dead name are chargeable at removal time (FONT-DEAD-NAME; BATCH-RFIX4 proposal 2, frutiger). (4) Severity grades — distinguish named-primary-unloaded (defect) from named-fallback-unloaded with loaded primaries and OS JP fonts behind (adjudication grade), and grade an inert stack supplement whose fallback chain ends at the original's generic form below the dead-name case (BATCH-RFIX9 proposal 2, BATCH-RDISP3 proposal 4, BATCH-RFIX15 (d)). (5) FONT-STACK signature — font-family/font-variable line share in a CSS-BODY block should classify it specifically rather than heuristically (BATCH-MPURE2 proposal 2, BATCH-MPURE3 proposal 2, BATCH-MPURE6 proposal 1, BATCH-MPURE12 proposal 2, BATCH-RFIX6 proposal 1, BATCH-U5 proposal 2). (6) Include-chain duplication — a load in a child duplicating a load in the included base candidate (same family, same specification), or replicating the base ORIGINAL's import set, is detectable by comparing @import sets across the include chain (BATCH-RFIX19 P1, BATCH-RDISP4 proposal 3, vanguard). (7) Delivered-channel verification — a P7 supplement counts only if the JP face is named in a DELIVERED CSS stack (module-css or code-css); body-text fragments do not count; grep stacks in CSS channels only, and add a signature for unwrapped CSS fragments in the body channel after a code exhibit (BATCH-U9 proposal 1, skipos). (8) Font-program inventory diff — compare loaded face sets (imports plus @font-face families), not only named-but-unloaded stacks, so a substitution where loads and stacks were rewritten together is visible (BATCH-RFIX15 (d), sunside). (9) Load closure — every family named in a stack or font variable should be loaded by an import/@font-face in the file or its resolved base chain, generics exempted (BATCH-RDISP7 proposal 3). Host-normalization shapes (bunny.net → Google Fonts css2 with the family set unchanged) are NON-substitutions and are recorded in the negative ledger, not charged here (BATCH-RDISP11 proposal 4, BATCH-MPURE1 P-1, BATCH-RFIX11 proposal 4).
