# KB-10 — Credit furniture missing or incomplete (no-credit, no-rate, credit-missing-fields)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** credit furniture / credit block absent, page unratable, or TASL fields missing / checker no-credit, no-rate, credit-missing-fields, or the 8-field count
- **Support:** 1 (static-diff)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

JP posting requires the credit block with the eight TASL-derived fields (タイトル,
原題, 著作権者, 作成年, 翻訳責任者, 翻訳年, 初訳時参照リビジョン, 元記事リンク). Candidates with no credit module
at all are also unratable (no Rate anywhere), and skeleton credits (2 of 8
fields) drop the original's attribution, including font/image credits.

## Static detection

Run the staff checker and read codes `no-credit`, `no-rate`,
`credit-missing-fields`; or grep the candidate for `credit:start` and count the
eight field labels in the credit block. Field values must be evidenced, never
invented.

blankstyle (no credit module at all, every field missing, theme unratable):

row 2. Fixed across FIX-CREDIT-A/B/C/D and FIX2-CREDIT waves.

## False positives and disposition

Created component pages deliberately leave `no-credit` (AGENTS.md sections 5-6);
this pattern is for theme candidates. The preview-vs-plain form itself is left
alone where out of scope (pataphysics keeps `credit:start`, warn only).

## Fix

Add `credit:start-preview` (it is rate-bearing) and only the missing fields,
values evidenced.

## Amendment (2026-11-17, patterns-wave3 extraction): field CONTENT, not just presence

This pattern's charge is field presence; a large proposal family from the review batches is that the checker verifies presence and form while the defects are in field CONTENT. Adopt as an extension of this pattern's detection (all repo-provable; values evidenced, never invented): (1) Pointer-form author values — a 著作権者 field or license-box `author=` parameter whose value is a pointer （原語版ページの作成者に同じ / の作者 / "the author of <page>"） while the original's prose, info block, license box, or CSS banner names a party is a finding; read BOTH carriers, since a partial repair can leave the license-box instance after the credit field is fixed (BATCH-RFIX9 proposal 3, BATCH-RDISP1 proposal 1, BATCH-RFIX11 proposal 2, BATCH-RFIX12 proposal 1, BATCH-RFIX5 proposal 2). (2) Named-party survival — where a wave deletes an info/credit block, any creator name it carried must survive in the replacement fields or the license-box author parameter; a generic paraphrase does not count (BATCH-MPURE1 P-6, BATCH-RFIX1 proposal 4). (3) Title field — the タイトル field must use the Japanese form the candidate's own body supplies (meta-title specimen or heading), not duplicate 原題; where no body form exists, degrade to a glyph-form report (BATCH-RFIX15 (b), BATCH-RFIX19 P2, BATCH-RFIX4 proposal 1). (4) 原題 and source-link text must equal the original credit block's title string character for character (TASL title-quotation check; BATCH-RFIX4 proposal 1). (5) 元記事リンク whose link text is a field name (ソース) rather than a title is flagged (BATCH-MPURE6 proposal 6). (6) Value sourcing — a 作成年 value appearing nowhere in the frozen original or equal to 翻訳年 is a sourcing finding; 初訳/改訳 fields must differ where sources.tsv records two distinct reference revisions (BATCH-RDISP5 proposal 2, BATCH-MPURE1 P-6). (7) License-line survival — license tokens (CC-BY-SA, license names) in the original's credit region must have a surviving equivalent in the candidate (BATCH-RDISP7 proposal 2). (8) Field count, not line count: attribution/provenance lines and nested includes riding inside a preview block do not add fields (BATCH-MPURE10 proposal 4). (9) Holder-content vs field-form: a pattern-3 closure must state whether it fixed the eight fields' FORM or added the charged NAME to the holder; a hit only in a CSS comment is not a holder-content fix (BATCH-U1 proposal 1). Provenance for a field resting on a hosting-path trace (no author named in the original) must use a standard sentence naming the trace (BATCH-RFIX2 proposal 4). This extension does not change the presence charge; it adds a content tier that the checker waves can implement incrementally.
