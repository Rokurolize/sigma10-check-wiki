# KB-07 — Interwiki-style include defect family (duplicate priority, missing priority, double include, missing include)

- **Class:** A. Theme defect, file-provable
- **Detection cost:** pure grep
- **Provability:** FILE-PROVABLE
- **Status:** adopted
- **Basis:** static-diff
- **Dedupe key:** interwiki-style include set / missing, missing-priority, duplicate-priority, or BHL split violation / include-set grep with the family rule
- **Support:** 1 (static-diff)
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

The translation-module frame is delivered by `:scp-jp:component:interwiki-style`
includes, each declaring a cascade `priority`. The JP convention is own code 1,
and for BHL-family themes normalize=1 / BHL=2 / own=3. A candidate whose own
include also declares priority=1 collides with the site's priority-1 normalize
load (console error on every combo, unpredictable cascade winner); a missing
`priority=` passes the unsubstituted default (KB-06); a duplicated include
double-applies; and a candidate with no interwiki-style include at all never
renders the translation-module frame.

## Static detection

Grep the candidate for `interwiki-style`. Record: count of includes, each
`priority=` value, each `theme=` argument. Charge: zero includes; any duplicate
priority value across the page's includes (counting the site normalize load as
priority 1); any include without `priority=`; BHL-family themes whose split is
not 1/2/3. Insert position should be before the first `[[iftags +テーマ]]`,
`theme=` = own draft-host code; where CSS is inlined and no code file exists,
the include takes neither `theme=` nor `css=`.

## Confirmed instances

Duplicate priority=1: bedbugs-theme, black-market, black-serpent (RENDER-S2-A
summary) and the BHL-derivative theme quoted in RENDER-S2 reports (`Interwiki:
encountered two themes with the same priority (1)` on all 8 combos of both
pages). Missing priority (rejected): bloodraven, caretaker-sigma (RENDER-S2-A).
Double include without priority: skipos (KB-06). Missing entirely: blankstyle,
dear-dictator (LOCALIZE-A rows 6/9), and the nine candidates fixed in
REPORT-GOSIGN2-FIX3-B.

## False positives and disposition

A single priority=1 on a non-BHL theme whose only load is its own code is the
settled form, not a collision; judge the full include set, not one line.

Two further shapes are not collisions, on FIX4-IWB counter-evidence
(themes left byte-unchanged by that lane):

Mutually exclusive parameter-gated loads. The same priority on
different targets is a collision only when the loads can co-fire.
normal carries six Parallel preset loads at priority=4 (candidate
L1079-1132) on top of its main Parallel load at priority=3 (L1024),
each preset wrapped in a conditional-comment parameter gate (the gated
span runs L1075 [!-- {$silver}-] to L1133 [!-{$cometic} --]; the six
gates are silver, deep, carbon, indust, night, cometic). Each block
renders only when the including page passes its named parameter, the
Parallel preset interface documented in the file, so at most one @4
target is active on any page and no two different targets ever coexist
at that priority. Test: before charging a repeated priority, read the
gates around each load; loads separated by mutually exclusive
parameter gates do not collide. Renumbering the presets would break
the documented preset interface, so the charge is not cured by
renumbering either. (The @import half of this shape is KB-65's
gated-block false positive; this paragraph is the priority half.)

Original-identical priority stacks. A stack that deviates from the
family rule charges only when the port introduced the deviation.
dia-de-muertos carries normalize@1 / BHL@2 / own@4 (candidate L27-35,
L428-431), and its original assigns the identical 1/2/4 (original
L16-24, L408-411): all distinct, no collision, no gap in the applied
chain. The "own should be 3" clause is the three-layer rule applied
mechanically to an original that deliberately numbers its own layer 4.
Test: compare the candidate's full priority stack against the
original's before charging a split violation; a stack identical to
the original's is the original's design, dispositioned as
counter-evidence, not fixed.

## Fix

Add `:scp-jp:component:interwiki-style` where absent; normalize priorities per
the family rule in AGENTS.md section 5.

## Variant merged 2026-11-17: required component include dropped entirely (A13-5)

A sibling shape of the missing-include charge: the original requires a
component, the JP port of that component exists in the repo, the
candidate's prose still credits the component, but the include itself is
gone. Confirmed instance: the-other-side-jp. Its original includes
`:fendsfox:component:betterbetterfootnote` (theme:the-other-side.txt
line 601) and its sample content uses `[[footnote]]` throughout; the
candidate keeps the footnotes and a `[[footnoteblock]]` and still names
the component in prose (line 29), but carries no include.
`component:betterbetterfootnote-jp` exists in the repo for exactly this
swap, and sibling candidates keep their footnote component in JP form
(basalt-jp, fuladh-theme-jp, highlighter-bhl-jp, internal-affairs-jp).
Fix: include `component:betterbetterfootnote-jp` at the position the
original's include occupied, and sweep other candidates whose prose
mentions a component their include list dropped. Source:
sigma10-review-20261117 findings/A13.md, finding A13-5. This merge was
chosen over KB-11 because the mechanism is an include-set defect
against the original (this pattern's family), not a CSS supplement
absence.
