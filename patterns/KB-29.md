# KB-29 — Hidden interwiki frame at render (`hidden-interwiki` on all combos)

- **Class:** B. Theme defect, triage only
- **Detection cost:** needs live probe
- **Provability:** TRIAGE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

The translation (interwiki) module's frame is present in the page's includes but
renders hidden on every engine/viewport combo: the theme's CSS (or its
interwiki-style delivery) sets the frame's container to a hidden state, or the
frame's styles never apply, so readers lose the translation module entirely even
though the include exists.

## Static detection

Triage: candidate includes interwiki-style (KB-07 passes) yet carries rules
setting `display: none` / `visibility: hidden` on interwiki frame selectors, or
overrides the frame container's dimensions to zero. Any such rule nominates the
theme; absence of such a rule does not clear it (the hiding can come from the
delivered code block, so include the candidate's code fragments in the grep).

## Confirmed instances

broken-world page and sample: `hidden-interwiki` on all 8 combos of both pages,
recorded as a theme-level, judgment-required line (RENDER-ROWS-RERUN16-PARTIAL;
RERUN16 summary). magicity: `hidden-interwiki` among its decisive T2 codes
(RERUN16 summary).

## False positives and disposition

The shared `styleFrame.html` stylesheet 404 (KB-43) is infrastructure, not this
pattern. A single-combo hidden line is a capture question (KB-44 family), not
this pattern; the charge needs the all-combos shape.

## Fix

Per-theme: remove or scope the hiding rule, or repair the interwiki-style
delivery so the frame paints.
