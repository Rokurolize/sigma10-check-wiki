# KB-51 — Scanner and extraction artefacts in include/dead-reference scans

- **Class:** E. Capture and measurement artefact, not a result
- **Detection cost:** needs live probe
- **Provability:** FILE-PROVABLE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

The campaign's own scanners manufacture gaps: include scans count `@@`-escaped
documentation examples as live targets and count unclosed fragment halves
(`info:start-standalone` / `info:end-standalone`) as missing pages; URL
extractors that truncate at parentheses manufacture dead references; a
`credit:start\b` regex overstates plain `credit:start` usage by matching
`credit:start-preview`. Acting on raw scanner output would port broken markup
and "fix" serving URLs.

## Static detection

Validate any counting method against known reference counts before trusting it
(the deps scan iterated four schemes before reproducing 195/198). For every
flagged target: check for `@@` escaping, check whether the target is a fragment
half, and probe the COMPLETE untruncated URL.

## False positives and disposition

This entry is the standing warning: a scanner flag is a nomination. The 2 real
DEPS gaps show the same scan also finds real items, so the recipe is re-triage,
not dismissal.

## Fix

Fix the scanner/regex, not the themes.
