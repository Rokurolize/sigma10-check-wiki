# KB-30 — Hidden login-status at render (`hidden-login`)

- **Class:** B. Theme defect, triage only
- **Detection cost:** needs live probe
- **Provability:** TRIAGE
- **Evidence source:** R/KNOWLEDGE-SEED-INVENTORY.md (compiled 2026-11-17 from the GOSIGN2 review reports and coordinator adjudications named there).

## Mechanism

The theme's header CSS hides `#login-status` (the account/login state block) at
desktop widths in one or both engines, so logged-out readers see no sign-in
state and the header contract differs from every other JP theme. The element is
in the DOM; the theme's rules make it invisible.

## Static detection

Triage: grep the candidate for `#login-status` rules and for header rules that
hide account-row children (`display: none`, `visibility: hidden`, zero-height
overflow on the header's right block) at desktop breakpoints.

## Confirmed instances

sodium page and sample: `hidden-login` on desktop in both engines, T3 confirms
login-state absence (RENDER-ROWS-G, CN14). shivering-night page and sample:
`hidden-login` in Chromium at 1366/768 (RENDER-ROWS-G, CN14).

## False positives and disposition

A theme that deliberately relocates login state (visible elsewhere in the
header) is a design question for T3, not an automatic charge; the confirmed
instances had no visible login state anywhere.

## Fix

Restore `#login-status` visibility in the candidate's header rules.
