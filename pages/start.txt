+ Sigma-10 display-check top
[[/=]]

[[div class="content-panel standalone centered"]]
[[div class="panel-body"]]
This page is the index (top) of the Sigma-10 display-check wikis. The purpose of this wiki set is to advance theme porting and SCP-JP's Sigma-10 migration. The same content is placed on both the Wikidot side (sigma10-jp-test, the side taken as the correct rendering) and the Wikijump side (SCP-JP Sigma-10), and each theme's decoration sample carries links to both sides side by side. The theme table is divided by the branch each theme was created in (its origin); a theme posted on SCP-JP as a translation also belongs to the table of the branch it was created in. For each theme it brings together the original and the port candidate (the JP port) samples, the prep state, and the staff application procedure. This wiki set is the environment for checking the Sigma-10 JP site theme (the production migration candidate), and each theme row's port candidate is displayed layered on top of this environment. This wiki set is also used to check Wikijump's behavior, but that is a secondary use. The record of how far Wikijump reproduces the existing articles is kept, with its purpose separated, at [[[start:wikijump-parity|Record of Wikijump rendering reproduction]]]. Wikijump is software still under development, and that some pages cannot be reproduced is a separate question from whether the migration is viable.
[[/div]]
[[/div]]

+ Overall state (at a glance)

* The theme table has **287 rows** across the origin subpages. review/sources.tsv records a review verdict of **PASS for 286 rows** and **EXCEPTION for 1 row** (Amethyst V2 Layout). The 286 are the pass-eligible population covered by the go-sign; 286 + 1 = 287. The exception still has a row, so the table accounts for all 287 rows.
* The generated verdict stamp of each review package (review/build_review.py) reports the same underlying result but flags files changed since the verdict head: **PASS 49**, **STALE 237**, **EXCEPTION 1** (49 + 237 + 1 = 287). A stamp reading "STALE" means the candidate file was revised after the verdict was computed; the stamp's own verdicts describe the pre-revision file. Both the record verdict and the factual stamp state are shown in each row's Status.
* **Ruling on STALE rows — post them; do not re-judge.** Every change made to a candidate after its verdict landed through the campaign's recorded, verified repair waves, and each is noted in its review package. The record verdict therefore stands, and a STALE row is read and posted exactly like a PASS row: its Status shows the record verdict (PASS) with the plain ground that the candidate was revised after the verdict through recorded repairs, and its package records the repair. STALE is not a new defect and is not a reason to hold a row back; it is the stamp honestly marking a file that changed after the verdict. The stamp regions themselves stay factual and are not edited.
* Named exceptions, in plain words: **Amethyst V2 Layout** has no port candidate. Its original is a ThemePreviewer shell — the substance is three g2lighter components on another wiki plus about 199 KB of externally hosted CSS, and the JP check wikis do not carry that component set, so there is no standalone page to port or review. **Sigma-10** is not a theme row at all; it is the Sigma-10 JP site theme itself, the environment candidate that this whole wiki pair exists to check. Its "port candidate" is the plain decoration sample with no theme layered on it.
* Where to start: the already-published pages are the priority verification surface, because what breaks on migration day is the live articles rather than the new port candidates. Begin with the existing-articles index below and the priority statement in "Existing articles (migration targets, priority)"; use the theme tables when doing the porting work itself.

+ Glossary of terms used in the tables

* **Prep** — our side's work state for a candidate: recording the reference revision, incorporating upstream diffs, re-scoring. When the work is finished it reads Complete. It is internal bookkeeping rendered in plain words; the integration-wave codes (EN1, CN9, KO1 and so on) are no longer shown, and the retired Check 5 note is written out as a plain phrase.
* **Check 5** — a retired per-sample interaction measurement. It measured interaction behaviour on each sample page (clicks, hovers, collapsibles and similar controls). It was retired on 2026-11-16 because its defect class is now judged through the render check and the visual checklist; it is not one of the campaign's five review tests (T1–T5) and is no longer run per sample. A record saying "Check 5 passed" means the measurement was taken and passed; "not measured: retired" means the measurement had been retired before that row was processed.
* **retired** — no longer performed or used. A retired check is kept in the historical record but is not part of the current test set.
* **Base** — the lineage a theme actually imports or includes: BHL (Black Highlighter), Basalt, Sigma-9, Sigma-10, Flopstyle, standalone, or a base component, sometimes read through a named receiver page.
* **Reference rev** — the original-language revision the JP version was translated from, as recorded in its credit (first translation, re-translation or first edition). The themed rows carry it; the two JP originals have no reference revision.
* **localcode** (local--code) — Wikidot's delivery path for a page's own CSS/JavaScript code block. A candidate's local--code URLs point at the display-check wiki and must be rewritten to the production host (scp-jp.wdfiles.com) when the candidate is posted.
* **localfiles** (local--files) — Wikidot's delivery path for a page's own attachments (images, fonts). These must be moved to SCP-JP storage and their URLs rewritten when the candidate is posted.
* **port candidate** — the JP port of one individual theme (theme:<slug>-jp) together with its display-check sample. This is the per-theme layer, displayed on top of the Sigma-10 JP site theme (the environment candidate) — a separate layer. Bare 「移植候補」 is avoided precisely because it would conflate the two.
* **STALE** — a verdict-stamp state meaning the candidate was revised after the ledger verdict, through the campaign's recorded repair waves (each noted in its package). It is not a new defect: the record verdict stands, and a STALE row is posted exactly like a PASS row. See the ruling in "Overall state (at a glance)".
* **Notation in the review packages** — package prose uses campaign shorthand (KB pattern ids, P-numbers, T1–T5, class (i)/(ii)/(iii) and wave names) that this glossary does not expand. The plain-word key is [[[https://github.com/Rokurolize/sigma10-check-wiki/blob/main/review/HOW-TO-READ.md|package notation key]]].

+ How to use this index

* Each row has three columns: Theme / Status / Details. "Theme" gives the title and the candidate slug in parentheses, so CN/KO rows are findable by slug. "Status" holds the prep state in plain words, the review verdict (PASS / STALE / NOT PASS / EXCEPTION with its one-line ground, sourced from review/sources.tsv and the generated package stamp), and the staff application procedure. "Details" holds the base, the reference rev, links to the original and the port candidate, and the diff page. The theme table is split into subpages reached from the contents below. The Wikijump reproduction state of existing articles is not carried in the theme table; it is kept separate at [[[start:wikijump-parity|Record of Wikijump rendering reproduction]]].
* Each theme has two samples, the "original" and the "port candidate", and each has links to its Wikidot and Wikijump versions. The only row without sample links is the Amethyst V2 Layout row; that row links only to the original (the CN branch).
* The links in each sample's cell are the Wikidot and Wikijump versions of the same sample page. [Wikidot] is the correct rendering, and [Wikijump] is the side under verification.
* Every sample page and theme page has this page (start) set as its parent page. You can return here at any time through the breadcrumb list.
* The canonical source of this page is pages/start.txt in the Git repository (sigma10-check-wiki). When editing, first edit and commit in the repository, then reflect the same text to both wikis. Do not edit from the wiki side first.

+ How to read this table (theme, status, details)

* "Theme" is the subject: the title plus the candidate slug in parentheses. "Status" holds the prep state in plain words, the review verdict with its one-line ground, and the staff application procedure. "Details" holds the base, the reference rev, the existing page, links to the original and port candidate samples, and the diff page.
* The state of an existing article itself is not carried in the theme row. The link to the existing page for each theme is in the "Existing page" part of Details, and its Wikijump reproduction state (match / mismatch) is brought together at [[[start:wikijump-parity|Record of Wikijump rendering reproduction]]].
* The "original" is a sample that @@[[include]]@@s the original-language (or origin-branch) theme page into a page of this check wiki and renders it on this wiki's Sigma-10 JP environment. Because it is not the original-language page itself, it can behave differently from the original-language page (measured 2026-11-15: EN's Aesthetic page is clickable, but the EN include specimen in this environment is not clickable). The final place to check a theme's own behavior is each theme's original-language (home) page.
* The "port candidate" is a sample with that theme's JP port applied.
* The common procedure for posting a port candidate to production SCP-JP: references inside a candidate that point at the display-check wiki (sigma10-jp-test) cannot be brought into production as they are. Rewrite the URLs of the candidate's own code (local--code) to the production host (scp-jp.wdfiles.com). Rewrite the URLs of the candidate's own attachments (local--files) after moving the files to production. Move images and fonts hosted on hosts other than SCP-JP storage to SCP-JP storage or a permitted CDN. Rewrite SCP-JP storage URLs that use http:// to https://. Obtain the candidate source text from the repository's `pages/<fullname>` file, which is byte-identical to the package's `candidate.txt`. After posting, check that the posted page's source matches the candidate bytes and that the theme's sample page renders with the theme applied.
* "Base" is the lineage a theme actually @imports / includes. The main values are BHL (Black Highlighter), Basalt, Sigma-9, Sigma-10, Flopstyle, standalone, and base component; where the base is read through a receiving page, that page name is recorded alongside. Flopstyle is treated as an independent theme base. "BHL (self-assembled)" means the theme belongs to the BHL family but does not read BHL's CDN directly and is assembled from its own composition (Monotypical).
* "Reference rev" is the reference revision at first translation / re-translation / first edition recorded in the JP version's credit (including the reference edition under the old notation). It is recorded for 284 of 286 rows; the remaining 2 rows are JP originals and have no reference rev.
* "Prep state" is our side's work state (recording the reference revision, incorporating diffs, re-scoring). When the work is done, it becomes "Complete". It is rendered in plain words: wave codes are not shown and the retired Check 5 measurement is written out as a plain phrase; see the glossary above.
* "Staff application procedure" is the operation SCP-JP staff actually perform after the materials are complete. The summary is in Status, and the link to the diff page is in Details.
* The "Sigma-10" row is not a theme row; it points at this check environment itself (the Sigma-10 JP site theme, the migration candidate). That row's "port candidate" is the plain decoration sample with no theme layered on it (theme-decoration-sample).
* In the "Quand le soleil se couche" row, the original and the port candidate are the same page. Because this theme's JP version has no independent local theme page, the original page itself doubles as the port candidate.
* The finalization state of the lineages is as follows. For the Sigma-10 body, EN's component:theme was redirected to Sigma-10 at rev 138 on 2024-11-26 (the body is managed on the Sigma-10 side). BHL continues to be updated, at rev 135 (2026-11-06). Basalt has had no source changes since rev 304 (2026-07-22, "Removed tiny table margin"). Flopstyle's last source change is rev 506 (2026-09-02). The base components depend on each theme's include targets, so they are judged by each row's reference rev.

+ Site-operations wikis (not themes; migration targets)

SB3 and FS are not theme names; they are SCP-JP operations wikis. On 2026-11-15, the CSS actually being served was fetched and checked (the REPORT24 measurements). Under Sigma-10, on both wikis, the header fixes "SCP財団" with a pseudo-element and hides the site name's h1 span. Re-expressing the site name and the subtitle is therefore mandatory. Each site package has a public review package on GitHub, linked in the first column. Neither package has a display-check sample page on the check wikis yet, so the procedure note in each row says where verification happens.
